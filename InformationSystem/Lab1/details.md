# 信息系统实验：老师额外答辩问题（中俄双语）

## 1. 什么是微服务？（Микросервисы）

**问题：Что такое микросервисы?**

**中文：** 微服务是一种软件架构，将大型应用拆分成多个独立服务。每个服务负责特定业务，可以独立开发、部署和扩展。

**俄语：** Микросервисы — это архитектура, в которой приложение разделено на небольшие независимые сервисы. Каждый сервис отвечает за свою бизнес-функцию и может развёртываться отдельно.

---

## 2. 什么是事务隔离级别？（Уровни изоляции транзакций）

**问题：Какие существуют уровни изоляции транзакций?**

**中文：** 事务隔离级别决定多个事务并发执行时，彼此能看到哪些数据变化。

| 隔离级别 | 中文解释 |
|---|---|
| Read Uncommitted | 允许脏读，但 PostgreSQL 实际按 Read Committed 处理 |
| Read Committed | 只能读取已提交的数据 |
| Repeatable Read | 同一事务内重复读取保持一致 |
| Serializable | 最严格，执行结果等价于某种串行执行顺序 |

**俄语：** Уровень изоляции определяет, какие изменения других транзакций видны текущей транзакции. Основные уровни: Read Uncommitted, Read Committed, Repeatable Read и Serializable.

---

## 3. JpaRepository 有什么优点？

**问题：В чём преимущества интерфейса JpaRepository?**

**中文：** `JpaRepository` 是 Spring Data JPA 的接口，提供现成的数据库操作方法，例如 `save()`、`findById()`、`deleteById()`，还支持分页、排序、批量操作及刷新持久化上下文。

**俄语：** `JpaRepository` предоставляет готовые методы для работы с базой данных: сохранение, поиск, удаление, пагинацию и сортировку. Это уменьшает количество шаблонного кода.

---

## 4. CrudRepository 和 JpaRepository 有什么区别？

**问题：Чем отличаются CrudRepository и JpaRepository?**

**中文：** `CrudRepository` 提供基本的增删改查操作，而 `JpaRepository` 在此基础上增加分页、排序以及 JPA 专属操作。

**俄语：** `CrudRepository` предоставляет базовые CRUD-операции. `JpaRepository` расширяет эти возможности, добавляя пагинацию, сортировку и специальные операции JPA.

**继承关系（Spring Data JPA 3.x）：**

```text
Repository
   └── CrudRepository
          └── ListCrudRepository
                 └── JpaRepository

PagingAndSortingRepository
          └── ListPagingAndSortingRepository
                 └── JpaRepository
```

`JpaRepository` 同时继承 CRUD 和分页排序相关接口。

---

## 5. Hibernate 有什么缺点？

**问题：Какие недостатки у Hibernate?**

**中文：** Hibernate 是 ORM 框架，主要缺点包括自动生成的 SQL 可能效率不高、容易出现 N+1 查询问题、复杂查询不够直观，以及缓存和实体状态管理增加调试难度。

**俄语：** Недостатки Hibernate: возможные проблемы производительности, проблема N+1 запросов, сложность оптимизации SQL и управления состоянием сущностей.

---

## 6. 为什么需要 Rate Limiting？

**问题：Зачем нужен Rate Limiting?**

**中文：** 限流用于限制用户或客户端在一定时间内的请求数量，防止接口滥用、服务器过载，并提高系统稳定性。

**例如：** 每个用户每分钟最多发送 100 次请求，超过限制可以返回 HTTP `429 Too Many Requests`。

**俄语：** Rate Limiting ограничивает количество запросов за определённое время. Он защищает сервер от перегрузки и злоупотреблений.

---

## 7. 什么是 Outbox Pattern？

**问题：Что такое паттерн Transactional Outbox?**

**中文：** Outbox 是一种保证数据库更新和消息发布可靠衔接的模式。业务数据和待发送消息在同一个本地事务中写入数据库，然后由独立进程将消息发送到消息队列。

它避免了“数据库更新成功，但消息未发送”的问题，但仍需要处理重复消息。

**俄语：** Transactional Outbox — это паттерн, при котором бизнес-данные и сообщение сохраняются в одной транзакции. Затем отдельный процесс отправляет сообщение в брокер сообщений. Это повышает надёжность обмена сообщениями.

---

## 8. 什么是 Saga Pattern？

**问题：Что такое паттерн Saga?**

**中文：** Saga 用于管理跨多个微服务的业务事务。它把一个大型事务拆分为多个本地事务，如果某一步失败，就通过补偿操作撤销之前的业务效果。

**例如：** 订单创建 → 扣除库存 → 支付。如果支付失败，可以通过补偿操作恢复库存、取消订单。

**俄语：** Saga — это паттерн управления распределёнными транзакциями. Он разделяет большую транзакцию на локальные транзакции. При ошибке выполняются компенсирующие действия.

---

## 9. Outbox 和 Saga 有什么区别？

**问题：В чём разница между Outbox и Saga?**

| 对比 | Outbox | Saga |
|---|---|---|
| 核心目的 | 可靠发布消息 | 协调分布式业务事务 |
| 解决的问题 | 数据已提交但消息丢失 | 多个服务的操作部分成功 |
| 主要机制 | 本地事务 + 消息转发 | 本地事务 + 补偿操作 |

**俄语：** Outbox обеспечивает надёжную отправку сообщений, а Saga управляет распределёнными бизнес-транзакциями с помощью компенсирующих действий.
