# 实验一答辩答案 · Ответы к защите лабораторной работы № 1

## 1. Шаблоны проектирования и архитектурные шаблоны

**中文**

设计模式是针对常见设计问题的可复用解决思路，主要描述类和对象的组织与协作。分为创建型、结构型和行为型，例如工厂、代理、策略和观察者模式。

架构模式描述系统整体结构、模块职责与依赖，例如分层架构、MVC 和客户端—服务器。两者主要区别在于作用范围。MVC 中，模型表示数据与业务逻辑，视图负责展示，控制器接收请求并协调处理；分层架构将表现、业务和数据访问职责分开，以降低耦合并便于维护。

**Русский**

Шаблон проектирования — типовое повторно используемое решение распространённой задачи организации классов и объектов. Выделяют порождающие, структурные и поведенческие шаблоны, например Factory, Proxy, Strategy и Observer.

Архитектурный шаблон описывает общую структуру системы, обязанности модулей и зависимости между ними. Примеры: слоистая архитектура, MVC и клиент-серверная архитектура. Главное различие — масштаб применения. В MVC модель представляет данные и бизнес-логику, представление отображает данные, а контроллер принимает запросы. Разделение слоёв представления, бизнес-логики и доступа к данным уменьшает связанность и упрощает сопровождение.

## 2. Платформа Jakarta EE. Виды компонентов

**中文**

Jakarta EE 是建立在 Java SE 上的企业应用开发规范集合，是 Java EE 的延续。规范定义 API 和行为，由兼容的服务器或运行时提供实现。容器为组件提供生命周期管理、依赖注入、安全与事务等服务。

主要组件包括 Servlet 等 Web 组件、CDI Bean、EJB 和消息驱动 Bean。EJB 会话 Bean 分为 Stateless、Stateful 和 Singleton，分别表示不保存特定客户端跨调用会话状态、保存客户端会话状态和共享单例组件。消息驱动 Bean 异步处理消息。JPA Entity 是持久化对象，不是 EJB；Servlet 容器也不等于完整 Jakarta EE 服务器。

**Русский**

Jakarta EE — набор спецификаций для корпоративных приложений на основе Java SE, продолжение Java EE. Спецификации определяют API и поведение, а совместимые серверы предоставляют реализации. Контейнер управляет жизненным циклом, зависимостями, безопасностью и транзакциями.

Основные компоненты — Servlet и другие веб-компоненты, CDI-бины, EJB и Message-Driven Beans. Session Beans бывают Stateless, Stateful и Singleton. Stateless не сохраняет состояние сеанса конкретного клиента между вызовами, Stateful сохраняет его, а Singleton предоставляет общий экземпляр. Message-Driven Bean асинхронно обрабатывает сообщения. JPA Entity — сохраняемый объект, а не EJB; Servlet-контейнер не равнозначен полному серверу Jakarta EE.

## 3. Jakarta EE. Управляемые бины. CDI-бины

**中文**

Managed Bean 是由容器管理的对象，容器负责创建、注入依赖及调用生命周期回调。手工 new 出来的对象不会自动获得这些容器服务。

CDI 是 Contexts and Dependency Injection，提供类型安全的依赖注入和上下文管理。@Inject 声明注入点，Qualifier 区分同类型实现，作用域决定实例生命周期。常见作用域有请求、会话、应用及 @Dependent；@Named 提供可在表达式语言中使用的名称，并非所有 Bean 都需要它。

典型生命周期为构造、依赖注入、@PostConstruct、使用、@PreDestroy。旧式 JSF Managed Bean、CDI Bean 和 Spring Bean 的管理机制不同，应当区分。

**Русский**

Управляемый бин — объект, жизненным циклом которого управляет контейнер: создаёт его, внедряет зависимости и вызывает методы жизненного цикла. Объект, созданный вручную, автоматически не получает эти сервисы.

CDI означает Contexts and Dependency Injection и обеспечивает типобезопасное внедрение зависимостей и управление контекстами. @Inject обозначает точку внедрения, квалификаторы различают реализации одного типа, а область видимости определяет время жизни экземпляра. Основные области — запрос, сеанс, приложение и @Dependent. @Named задаёт имя, например для EL, и требуется не каждому бину.

Типичный жизненный цикл: создание, внедрение зависимостей, @PostConstruct, использование и @PreDestroy. Исторические JSF Managed Beans, CDI-бины и Spring-бины следует различать.

## 4. Концепция ORM. Hibernate и EclipseLink: особенности, API, сходства и отличия

**中文**

ORM 是对象—关系映射：类对应表，对象对应记录，属性对应列，关联对应外键或关联表。它减少重复数据访问代码，并处理对象模型与关系模型在身份、继承和关联表达上的差异，但不能代替 SQL 和事务知识。

Hibernate 与 EclipseLink 都是 ORM 框架和 JPA 实现，支持实体映射、关联、查询、事务与缓存。使用标准 API 时，可以使用 EntityManager、JPQL、Criteria API 和原生 SQL。

Hibernate 还提供 Session、SessionFactory 和 HQL 等专用 API；EclipseLink 源自 TopLink，提供自己的查询、缓存和 weaving 扩展。两者的配置和优化方式不同，选择应考虑兼容性与实际需求；更换 provider 仍需测试。Hibernate Validator 是校验库，不是 Hibernate ORM。

**Русский**

ORM — объектно-реляционное отображение: классы соответствуют таблицам, объекты — строкам, поля — столбцам, а связи — внешним ключам или таблицам связей. ORM уменьшает повторяющийся код и решает различия моделей в идентичности, наследовании и связях, но не заменяет знания SQL и транзакций.

Hibernate и EclipseLink — ORM-фреймворки и реализации JPA. Они поддерживают отображение сущностей, связи, запросы, транзакции и кеширование. Стандартный API включает EntityManager, JPQL, Criteria API и native SQL.

Hibernate дополнительно предоставляет Session, SessionFactory и HQL. EclipseLink основан на TopLink и имеет расширения для запросов, кеширования и weaving. Настройки и способы оптимизации отличаются; выбор зависит от совместимости и требований, а замена провайдера требует тестирования. Hibernate Validator — библиотека валидации, а не Hibernate ORM.

## 5. Технология Jakarta Persistence. Особенности, API, интеграция с ORM-провайдерами

**中文**

Jakarta Persistence，即 JPA，是对象持久化标准，不是具体 ORM 实现。它定义实体映射、生命周期、持久化上下文和查询 API，由 EclipseLink、Hibernate 等 provider 实现，并通过 JDBC 连接数据库。

实体使用 @Entity、@Id 等注解，通过 @Table、@Column 和关联注解描述映射。EntityManagerFactory 创建 EntityManager，后者管理持久化上下文中的实体。主要操作有 persist、find、merge、remove、flush、refresh；查询可用 JPQL、Criteria API 或原生 SQL。

实体有新建、托管、游离和待删除状态。托管实体的修改会被跟踪；flush 同步数据库但不等于提交；merge 返回接收状态的托管实例，不保证原对象成为托管对象。配置可通过 persistence.xml 或程序化配置完成，事务由应用或容器管理。

**Русский**

Jakarta Persistence, или JPA, — стандарт персистентности объектов, а не конкретная ORM-библиотека. Он определяет отображение, жизненный цикл, контекст персистентности и API запросов. Провайдеры, например EclipseLink и Hibernate, реализуют стандарт и взаимодействуют с БД через JDBC.

Сущность обозначается @Entity и имеет @Id. Отображение задают @Table, @Column и аннотации связей. EntityManagerFactory создаёт EntityManager, управляющий сущностями в контексте персистентности. Основные операции: persist, find, merge, remove, flush и refresh. Доступны JPQL, Criteria API и native SQL.

Состояния сущности: новая, управляемая, отсоединённая и удаляемая. Изменения управляемых объектов отслеживаются. flush синхронизирует изменения, но не завершает транзакцию. merge возвращает управляемый экземпляр с перенесённым состоянием. Настройка выполняется через persistence.xml или программно; транзакциями управляет приложение или контейнер.

## 6. Технология Jakarta Data

**中文**

Jakarta Data 是通过声明式 Repository 接口访问数据的标准。开发者声明接口、操作和查询，兼容的 provider 提供实现，从而减少 DAO 的重复代码。它提供数据操作、查询、排序和分页等抽象，具体能力取决于版本与实现。

它与 JPA 处于不同层次：JPA 规定关系映射和实体管理，Jakarta Data 提供更高层的仓库访问接口，可以基于 JPA，也可用于其他存储方式。它不替代数据库和底层持久化实现，也不等于 Spring Data。

**Русский**

Jakarta Data — стандарт декларативного доступа к данным через интерфейсы Repository. Разработчик объявляет операции и запросы, а совместимый провайдер создаёт реализацию. Это уменьшает повторяющийся код DAO. Стандарт предоставляет абстракции операций, запросов, сортировки и пагинации; возможности зависят от версии и реализации.

Jakarta Data и JPA находятся на разных уровнях. JPA описывает объектно-реляционное отображение и управление сущностями, а Jakarta Data — более высокоуровневые репозитории. Он может использовать JPA или другие технологии хранения, не заменяет базу данных и не равнозначен Spring Data.

## 7. Платформа Spring. Сходства и отличия с Java EE

**中文**

Spring Framework 是模块化 Java 框架，核心是 IoC 容器与依赖注入，还提供 AOP、事务抽象、Spring MVC 和数据访问集成。Bean 通过组件注解或 Java 配置注册，由 ApplicationContext 管理。

Spring 与 Java/Jakarta EE 都支持组件化、生命周期、依赖注入、事务和 Web 开发。区别在于 Jakarta EE 是具有多种实现的规范集合，Spring 是具体框架及生态。Spring 可以集成 Servlet、JPA、Validation 等 Jakarta 标准，两者并不互斥。

Spring MVC 使用 DispatcherServlet 分派请求；DI 降低组件耦合；AOP 将事务等通用功能与业务代码分离。默认 singleton 是容器内的单例，不自动保证线程安全。

**Русский**

Spring Framework — модульный Java-фреймворк, основой которого являются IoC-контейнер и внедрение зависимостей. Он также предоставляет AOP, транзакции, Spring MVC и интеграцию доступа к данным. Бины регистрируются аннотациями или Java-конфигурацией и управляются ApplicationContext.

Spring и Java/Jakarta EE поддерживают компонентный подход, жизненный цикл, DI, транзакции и веб-разработку. Jakarta EE — набор спецификаций с разными реализациями, а Spring — конкретный фреймворк и экосистема. Spring интегрируется с Servlet, JPA и Validation, поэтому эти подходы не исключают друг друга.

В Spring MVC запросы распределяет DispatcherServlet. DI уменьшает связанность, а AOP отделяет сквозные функции, например транзакции, от бизнес-кода. Singleton означает один экземпляр бина в контейнере и сам по себе не гарантирует потокобезопасность.

## 8. Spring Boot

**中文**

Spring Boot 基于 Spring，简化依赖配置、应用启动与部署。主要能力包括 starter 依赖组合、兼容版本管理、自动配置、外部配置及带嵌入式服务器的可执行 JAR。

@SpringBootApplication 组合应用配置、组件扫描与自动配置。自动配置依据 classpath、配置属性和已有 Bean 等条件工作，也允许开发者覆盖默认方案。参数可通过 application.yml、环境变量或启动参数设置。

Boot 不替代 Spring MVC 或 ORM：MVC 处理 Web 请求，ORM 处理对象持久化，Boot 简化它们的组装与启动。应用通常可直接用 java -jar 运行，无需另行安装 Web 容器。

**Русский**

Spring Boot основан на Spring и упрощает настройку зависимостей, запуск и развёртывание. Он предоставляет starter-зависимости, управление совместимыми версиями, автоконфигурацию, внешние настройки и исполняемый JAR со встроенным сервером.

@SpringBootApplication объединяет конфигурацию приложения, сканирование компонентов и автоконфигурацию. Она зависит от библиотек в classpath, свойств и существующих бинов; разработчик может переопределить стандартные настройки. Параметры читаются из application.yml, переменных окружения или аргументов запуска.

Boot не заменяет Spring MVC или ORM: MVC обрабатывает веб-запросы, ORM сохраняет объекты, а Boot упрощает их сборку и запуск. Обычно приложение запускается через java -jar без отдельной установки веб-контейнера.

## 9. Spring Data

**中文**

Spring Data 是 Spring 的数据访问项目家族，包括 JPA、JDBC、MongoDB 等模块，因此不能把整个 Spring Data 都称为 ORM。

Spring Data JPA 在 JPA 之上提供 Repository 抽象。开发者声明继承 JpaRepository<Entity, ID> 等接口的仓库，由框架生成实现代理，提供 CRUD、分页、排序、方法名派生查询、@Query 和自定义实现。findById 返回 Optional，找不到时返回 Optional.empty()。

对象映射与 SQL 执行仍由 JPA provider 完成。Spring Data 减少重复代码，但事务、复杂查询和性能仍需设计。它属于 Spring 生态；Jakarta Data 是 Jakarta 标准，二者 API 不能直接互换。

**Русский**

Spring Data — семейство проектов доступа к данным в экосистеме Spring. Оно включает JPA, JDBC, MongoDB и другие модули, поэтому не является ORM в целом.

Spring Data JPA предоставляет абстракцию Repository поверх JPA. Разработчик объявляет интерфейс, например наследник JpaRepository<Entity, ID>, а инфраструктура создаёт реализацию-прокси. Поддерживаются CRUD, пагинация, сортировка, запросы по именам методов, @Query и собственные реализации. findById возвращает Optional, а при отсутствии записи — Optional.empty().

Отображение объектов и выполнение SQL остаются задачей JPA-провайдера. Spring Data уменьшает повторяющийся код, но не отменяет проектирование транзакций, запросов и производительности. Spring Data относится к Spring, а Jakarta Data является стандартом Jakarta; их API не взаимозаменяемы.
