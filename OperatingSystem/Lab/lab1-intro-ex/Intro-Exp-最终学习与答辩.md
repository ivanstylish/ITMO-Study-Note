## B1. 目标、变体与假设 / Цель, вариант и гипотеза

### B1.1. 真正比较什么？ / Что сравнивается?

**中文：**Read 是沿 child 指针遍历记录；Write 在遍历过程中把 value 加 1。Write 仍包含读取，不是独立的纯写吞吐测试。Cache 是文件 page cache；10M 在本生成器中是 10 MiB；Seq 是物理位置与遍历顺序一致。

**RU:** Read означает обход записей по ссылкам child. Write выполняет тот же обход и увеличивает value на единицу. Поэтому сравниваются чтение и чтение с обновлением, а не два независимых потока чистого чтения и записи. Cache относится к файловому page cache, 10M означает 10 МиБ, а Seq — последовательный физический порядок.

**中文：**组内比较 A/B 和 C/D，改变读写因素；跨 API 比较 A/C 和 B/D，用于解释不同实现。不能同时更改缓存、文件大小、ITER，再把差异全部归因于写入。

**RU:** Сравнения A/B и C/D изменяют режим работы внутри одного API. Сравнения A/C и B/D показывают различие реализаций. Если одновременно изменить кеш, размер или ITER, влияние записи будет смешано с влиянием других факторов.

### B1.2. 怎样解释事前假设？ / Как объяснить предварительную гипотезу?

令两个 API 各自的总体平均差为：

$$
\Delta=\mu_{\mathrm{Write}}-\mu_{\mathrm{Read}},\qquad
H_0:\Delta\leq0,\qquad H_1:\Delta>0.
$$

**中文：**预期更新更慢，依据是源码增加的工作。read/lseek 增加定位与 write；mmap 增加对共享页面的修改及相关处理。事前没有规定精确倍数。报告采用“配对差值的双侧 95% CI 下界为正”的预设判据；这是方向性假设的保守判据。

**RU:** Ожидается, что обновление будет медленнее из-за дополнительной работы в исходном коде. В read/lseek добавляются позиционирование и write, в mmap — изменение общих страниц и их обработка. Точный коэффициент заранее не задаётся. Положительная нижняя граница двустороннего 95% интервала разности является заранее выбранным консервативным критерием для направленной гипотезы.

**中文：**这是对已知程序行为的确认性实验。假设在本次 pilot 和正式测量之前固定；不能把这一记录说成所有历史运行都已事前登记。两个 API 的 95% 区间分别解释，不声称所有区间同时覆盖的概率也是 95%。

**RU:** Это подтверждающее исследование известных программ. Гипотеза зафиксирована до данного пилота и основной серии. Уровень 95% относится к каждому сравнению отдельно; он не означает 95% одновременного покрытия всех интервалов.

**知识点 / Понятия：**控制变量 / контролируемые факторы；总体均值 / среднее генеральной совокупности；零假设与备择假设 / нулевая и альтернативная гипотезы；预先规划 / предварительное планирование。

**教材关联：**BPF PDF 第 160–169 页：先定义可测量目标、识别负载，再选择分析方法。

**中文：**主机有 14 个物理核、20 个逻辑处理器；WSL 显示 10 核×2 线程是客体拓扑，不能把它当作物理硬件事实。`taskset -c 2` 的 2 是一个逻辑 CPU 的编号，不表示“用两个核”；编号通常从 0 开始。

**RU:** Windows показывает 14 физических ядер и 20 логических процессоров. Представление WSL «10 ядер по два потока» является гостевой топологией. В `taskset -c 2` число 2 — номер одного логического CPU, а не количество ядер.

**中文：**文件在 Ubuntu 家目录的 ext4 上，避免 `/mnt/c`、`/mnt/d` 的共享文件访问路径。Windows 与 WSL 仍共享物理 CPU、内存和存储；关闭 Linux 程序并不能隔离 Windows 后台。

**RU:** Файл размещён на ext4 в домашнем каталоге Ubuntu, чтобы не использовать путь через общую файловую систему Windows. Однако Windows и WSL разделяют физические ресурсы; отсутствие лишних Linux-процессов не гарантирует отсутствия фоновой нагрузки хоста.

**中文：**RAM 为 7835.2 MiB，图占约 `10/7835.2×100%=0.13%`，适合全部预读进文件缓存。不能由此声称它全部位于 CPU L1/L2/L3。WSL governor 不可用，固定 CPU 频率、温度、Turbo 和物理核绑定未确认。

**RU:** Граф занимает около 0,13% RAM гостя, поэтому его можно полностью прогреть в файловом кеше. Это не доказывает размещения всего графа в аппаратных кешах CPU. Governor недоступен; постоянная частота, температура, Turbo и привязка к физическому ядру не подтверждены.

**中文：**guest load average 从 0.42/0.23/0.10 到 1.03/0.65/0.30；它是 1/5/15 分钟的平均负载，不是 CPU 使用百分比。Linux 中还可能包含不可中断等待任务。实验自己也会提高运行后的平均负载。

**RU:** Load average показывает среднюю нагрузку за 1, 5 и 15 минут, а не процент использования CPU. В Linux учитываются также некоторые задачи в непрерываемом ожидании. Основная серия сама может увеличить послесерийное значение.

**中文：**guest 快照空闲 99.7%，host 快照 CPU 18%，二者采样范围及时间不同；不能由 guest 空闲推断主机完全安静。swap 只占约 0.3 MiB，也不能单凭“占用量小”证明整个测量期间从未发生换页。

**RU:** Снимки гостя и хоста относятся к разным областям и моментам наблюдения. Высокая доля простоя гостя не доказывает полной изоляции хоста. Малое использование swap само по себе не доказывает отсутствие всех операций подкачки во время серии.

## B3. 图文件与 baseline / Данные и ознакомительные запуски

### B3.1. 文件中有什么？ / Как устроен файл?

| 内容 / Поле | 大小 / Размер | 作用 / Назначение |
|---|---:|---|
| 文件头 / заголовок | 40 字节 / байт | 格式、顶点数、记录大小、根索引等 / формат, число вершин, размер записи, корень |
| `value` | 8 | 更新的数值 / изменяемое значение |
| `degree` | 4 | 出度 / число исходящих рёбер |
| 保留字段 / резерв | 4 | 记录布局的一部分 / часть формата |
| `child` | 8 | 下一顶点索引 / индекс следующей вершины |
| 一条记录 / запись | 24 | 一个顶点 / одна вершина |

```text
file_bytes = 10 * 1024 * 1024 = 10485760
nodes = (10485760 - 40) / 24 = 436905
offset(i) = 40 + i * 24
Seq: 0 -> 1 -> 2 -> ... -> 436904 -> end
file_pages = 10485760 / 4096 = 2560
```

**中文：**10M 是字节容量，不是 1000 万顶点。Seq 的相邻顶点位于相邻记录位置，有较好空间局部性。一次循环沿 child 走完整个链，最后顶点的 degree 为 0。每次打印处理了 436905 个顶点，用于验证完成了完整遍历。

**RU:** 10M — размер файла, а не десять миллионов вершин. У Seq соседние вершины лежат в соседних записях, что даёт пространственную локальность. Программа следует по child до вершины без потомка; сообщение о 436905 обработанных вершинах проверяет полноту обхода.

**中文：**`--topology chain` 表示随机物理排列的链，不是 Seq。两者逻辑上都是链，但文件位置与访问局部性不同。这里的“顺序图数据”也不是 UML 时序图。

**RU:** Пресет chain создаёт цепь со случайным физическим порядком. Sequential и chain имеют форму цепи, но различную локальность. Последовательный граф данных не является UML-диаграммой последовательности.

### B3.3. 为什么 baseline 测 16 种？ / Почему 16 вариантов baseline?

**中文：**课程 4.3 的熟悉阶段列出两个图和两种开关的组合；第 5 节对 mmap 重复。因此为 `2 拓扑 × 2 API × 2 读写 × 2 缓存 = 16`，每种一个进程、一个遍历。正式实验仍只分析固定 Seq、Cache 的四组。Baseline N=1 只能认识行为和验证功能，不能估计重复运行的方差；它不是 N=10 的 pilot。

**RU:** Ознакомительный этап охватывает два графа и комбинации флагов; для mmap он повторяется. Получаются 16 запусков, по одному обходу. Основная серия варианта содержит только четыре группы при Seq и Cache. Один baseline-запуск проверяет работу программы, но не оценивает межзапусковую дисперсию и не заменяет пилот.

| API | 图 / Граф | 操作 / Режим | Cache，s | NoCache，s |
|---|---|---|---:|---:|
| read/lseek | Seq | Read | 0.09 | 25.68 |
| read/lseek | Seq | Write | 0.23 | 88.89 |
| read/lseek | Rand | Read | 0.11 | 41.97 |
| read/lseek | Rand | Write | 0.24 | 101.75 |
| mmap | Seq | Read | 0.00 | 0.00 |
| mmap | Seq | Write | 0.00 | 0.00 |
| mmap | Rand | Read | 0.01 | 0.01 |
| mmap | Rand | Write | 0.02 | 0.02 |

**中文：**表中的 `0.00` 是 GNU time 的显示分辨率为 0.01 s 导致的，不是程序瞬间完成。单次数据能观察到现象，不能据此精确宣布“随机比顺序慢多少倍”。

**RU:** Значение 0,00 связано с разрешением вывода GNU time 0,01 с, а не с нулевой длительностью. Один запуск позволяет заметить поведение, но не даёт точной оценки коэффициента между Rand и Seq.

**中文：**在当前 Linux 实现中，read/lseek 的 NoCache 使用 `O_DIRECT`；可能涉及反复读取对齐块以及写入时的读改写。它不等于关闭 SSD 内部缓存，也不自动提供 `O_SYNC` 的持久化保证。mmap NoCache 仍走 page cache，只增加 `madvise` 建议，写模式还有 `msync(MS_SYNC)`。NoCache 因而不是两个 API 完全相同的冷缓存实验；很长的 baseline 运行不表示正式四组也必须运行很久。

**RU:** В read/lseek используется O_DIRECT, с особенностями выровненных операций и обновления блоков. Это не отключение внутреннего кеша SSD и не автоматическая гарантия O_SYNC. В mmap остаётся page cache: применяются рекомендации madvise, а при записи — msync. Поэтому NoCache не задаёт одинаковый холодный кеш для двух API. Долгий baseline не означает, что основная серия должна быть такой же долгой.

**知识点 / Понятия：**二进制格式 / бинарный формат；偏移 / смещение；空间局部性 / пространственная локальность；文件缓存 / файловый кеш；对齐 I/O / выровненный ввод-вывод。

**教材关联：**part1 第 15–16、60 页；BPF 第 500–503 页。O_DIRECT 的语义参考 [open(2)](https://www.man7.org/linux/man-pages/man2/open.2.html)。

### B4.2. 为什么恢复、预热、交错？ / Зачем восстановление, прогрев и чередование?

**中文：**每个进程前恢复文件；Write 进程内连续 20 遍，不在每遍后恢复，因此 value 可以累计加 20，后面的遍历也可能面对已修改页面。B、D 使用相同规则。两次预热是每个配置两个完整进程，即正式系列的 8 个额外进程；它们与每次进程前 cat 预读是两种准备层次。

**RU:** Файл восстанавливается перед процессом, но не между двадцатью обходами. В Write значение может увеличиться на двадцать, а последующие обходы используют уже изменённые страницы. Правило одинаково для B и D. Два прогрева на конфигурацию дают восемь дополнительных процессов; это отдельная процедура от чтения файла через cat перед каждым запуском.

**中文：**顺序依次为 ABCD、BCDA、CDAB、DABC，循环重复。这样避免全部 A 先跑完、CPU 变热后才运行 B 的时间顺序偏差。它不能证明完全消除了热变化或全部观测独立。

**RU:** Порядок ABCD, BCDA, CDAB, DABC повторяется циклически. Это распределяет временной дрейф между режимами и уменьшает смешение эффекта с прогревом CPU. Чередование не доказывает отсутствия всех изменений среды или независимости всех наблюдений.

### B4.3. N 的计算要能讲出来 / Как рассчитано N?

先定义每组目标半宽 `E=0.05×pilot 平均值`，再计算：

$$
n_0=\max\left(2,\left\lceil\left(\frac{1.96s_p}{E}\right)^2\right\rceil\right),
\qquad
t_{0.975,n-1}\frac{s_p}{\sqrt n}\leq E.
$$

| 组 | pilot 均值 / среднее，ms/遍历 | pilot s，ms/遍历 | 目标 / цель E | 初始 / начальное n₀ | t 修正 / уточнение t |
|---|---:|---:|---:|---:|---:|
| A | 99.773924 | 1.369894 | 4.988696 | 2 | 3 |
| B | 247.566585 | 4.749459 | 12.378329 | 2 | 3 |
| C | 1.660815 | 0.203505 | 0.083041 | 24 | 26 |
| D | 3.543730 | 0.300423 | 0.177187 | 12 | 14 |

$$N=\max(30,3,3,26,14)=30.$$

**中文：**先用 1.96 作近似，再用随自由度变化的 t 分位数反解。最严格的 pilot 需求是 C 的 26 次；事前规则还有最低 30 次，以保留分布图样本并为短 pilot 留余量，所以统一 N=30。不能说“30 是统计学规定”或“看到结果很漂亮才选 30”。pilot 的方差估计本身有误差，计划不是精度保证。

**RU:** Сначала используется нормальное приближение 1,96, затем квантиль t уточняется с учётом степеней свободы. Самое большое требование пилота — 26 запусков для C. Предварительный минимум 30 сохраняет число точек для распределений и запас к короткому пилоту, поэтому выбрано общее N=30. Это не универсальное правило статистики и не выбор после просмотра основного результата. Пилотная оценка разброса тоже неточна.

**中文：**本次 pilot 共 40 条，正式共 120 条。pilot 不加入正式样本，8 个正式预热进程也不加入。全部有效正式点保留；1.5×IQR 只描述异常点，不用于删数据。

**RU:** Пилот содержит 40 строк, основная серия — 120. Пилот и восемь основных прогревочных процессов не включены в основное N. Все корректные основные точки сохранены; правило 1,5×IQR используется только для описания.

### B4.5. 一个 wall 到底计入什么？ / Что входит в wall?

```text
Outside timer:
compile -> generate -> restore -> sync -> cat

MONOTONIC start
  -> /usr/bin/time -> taskset -> program
  -> open/map -> 20 traversals -> close/unmap -> log output
  -> child process exits
MONOTONIC end
```

**中文：**`mono_time.py` 计时区间包含子进程启动、GNU time、taskset、程序打开/映射、20 遍与日志输出，不包含 Python 解释器自身启动、编译、生成和文件准备。所以 `wall/20` 是“进程总时间按遍历归一化”，不是循环本体的纯执行时间。短 mmap 进程更容易受到启动开销影响。

**RU:** Интервал включает запуск дочернего процесса и оболочек, открытие или отображение файла, двадцать обходов и вывод. Запуск интерпретатора Python и подготовка файла исключены. Поэтому wall/20 — нормированное время процесса, а не чистое время тела цикла. У коротких mmap-процессов доля запуска заметнее.

**知识点 / Понятия：**统计单位 / единица наблюдения；伪重复 / псевдорепликация；pilot / пилотная серия；交错 / интерливинг；工具侵入性 / влияние измерения。

**教材关联：**BPF 第 160–169、1236 页；统计公式与本次 N 见报告第 5–7 页。

## B5. 统计结果与图 1 / Статистика и рисунок 1

### B5.1. 单位与公式 / Единицы и формулы

如果进程 wall 为 T 秒，先归一化：

$$
x_i=\frac{1000T_i}{20}\quad\text{ms/遍历},\qquad
\bar x=\frac{1}{N}\sum_{i=1}^N x_i.
$$

$$
s=\sqrt{\frac{\sum_{i=1}^N(x_i-\bar x)^2}{N-1}},\qquad
SE=\frac{s}{\sqrt N},\qquad
CI_{95\%}=\bar x\pm t_{0.975,N-1}SE.
$$

| 符号 | 中文 | Русский |
|---|---|---|
| μ | 想估计的总体平均值 | Среднее генеральной совокупности |
| x̄ | 这组样本的平均值 | Выборочное среднее |
| s | 单次进程归一化结果的波动 | Выборочное стандартное отклонение наблюдений |
| SE | 平均值估计的标准误 | Стандартная ошибка среднего |
| N−1 | 自由度 | Степени свободы |
| t₀.₉₇₅ | 双侧 95% 区间的分位数 | Квантиль для двустороннего 95% интервала |
| h=t×SE | 区间半宽 | Полуширина интервала |

**中文：**方差估计分母使用 N−1，因为平均值也是从这些数据估计的，损失一个自由度。未知总体方差，用样本 s，因此选 Student t。N=30 时自由度 29，t≈2.04523；不因 N=30 就假定每次计时呈正态。若观测有强依赖或严重长尾，t 区间的适用性还需考虑。

**RU:** Знаменатель N−1 учитывает оценку среднего по тем же данным. При неизвестной дисперсии применяется выборочное s и квантиль Стьюдента. Для N=30 число степеней свободы равно 29, t≈2,04523. Само N=30 не доказывает нормальность отдельных наблюдений; зависимость и сильные хвосты ограничивают интерпретацию интервала.

| A | 30 | 100.555595 | 2.778765 | [99.517987; 101.593203] |
| B | 30 | 246.274694 | 5.294152 | [244.297825; 248.251563] |

**A 的算例 / Пример A：**


**RU:** Интервал не означает, что в нём находятся 95% отдельных запусков. При многократном повторении процедуры в подходящих условиях около 95% построенных интервалов покрывают фиксированное среднее генеральной совокупности. Систематическая ошибка часов в них не включена.

## B6. 分布图与假设检查 / Распределения и проверка гипотезы

### B6.1. 图 2 看什么？ / Что показывает рисунок 2?

![报告图 2：读写叠加分布 / Распределения Read и Write](D:/Study-Note/OperatingSystem/Lab/lab1-intro-ex/report-completion-20261012/assets/read-write-density-ru.svg)

**中文：**每个 API 的 Read 与 Write 放在同一面板，用相同的分箱边界。X 是 ms/遍历，Y 是密度；每种模式的柱面积之和为 1。read/lseek 的箱宽约 2.428120 ms，mmap 约 0.205792 ms。两模式分箱相同便于比较；不同 API 的刻度和箱宽不同。

**RU:** Read и Write одного API показаны в одной панели с общими границами столбцов. Ось X — мс/обход, Y — плотность; площадь каждой гистограммы равна единице. Ширины интервалов составляют примерно 2,428120 мс и 0,205792 мс для разных API. Между панелями масштабы различаются.

密度计算 / Плотность：

$$f_j=\frac{c_j}{N\,b}.$$

其中 c_j 是箱内次数，b 是箱宽；/ Здесь c_j — число наблюдений в столбце, b — его ширина.

**中文：**红色 Write 右移意味着观察到更长时间；mmap 有一些较慢的点。不要把最高柱高度当平均值，也不能凭分布外观宣布正态分布。

**RU:** Сдвиг Write вправо означает большие наблюдаемые времена. У mmap видны отдельные медленные процессы. Высота самого высокого столбца не является средним, а внешний вид не доказывает нормальность.

| 方法 | 中文 | Русский |
|---|---|---|
| 直方图 / гистограмма | 按箱统计；受箱宽与边界影响 | Группирует точки по интервалам; зависит от ширины и границ |

**中文：**本报告实际用直方图，没有运行 KDE。二者是分布可视化方法，不自动检验正态性。

**RU:** В отчёте использована гистограмма, а не KDE. Оба способа визуализируют распределение, но не являются автоматической проверкой нормальности.

### B6.2. 为什么用配对差值？ / Зачем парная разность?

同轮计算 / Для каждого раунда：

$$d_r=x_{\mathrm{Write},r}-x_{\mathrm{Read},r},\qquad
CI_{\Delta}=\bar d\pm t_{0.975,29}\frac{s_d}{\sqrt{30}}.$$

| API | 30 对的平均差 / средняя разность，ms/遍历 | s_d | 95% CI |
|---|---:|---:|---|
| read/lseek | 145.719099 | 4.502238 | [144.037936; 147.400262] |
| mmap | 1.874277 | 0.347595 | [1.744483; 2.004071] |

**中文：**相邻同轮观测可以部分抵消共同环境变化。标准差要从 30 个差值计算，不能简单相加两个均值 CI 的半宽。两者下界均大于零，按预设模型支持更新更慢；不是“证明任何环境下都如此”。

**RU:** Наблюдения одного раунда могут частично учитывать общие изменения среды. Стандартное отклонение вычисляется по тридцати разностям; полуширины отдельных интервалов нельзя просто складывать. Обе нижние границы положительны и поддерживают гипотезу в принятой модели, но не доказывают её для любых условий.

$$R=\frac{\bar x_{\mathrm{Write}}}{\bar x_{\mathrm{Read}}},\qquad
\text{增长 / прирост}=(R-1)\times100\%.$$

read/lseek：R=2.449140，增加约 144.914%；mmap：R=2.153954，增加约 115.395%。/ Отношения равны 2,449140 и 2,153954; прирост составляет 144,914% и 115,395%.

**中文：**mmap 差值 CI 相对半宽约 6.93%，不违反 5% 目标：预设 5% 是各组均值的目标，不是差值相对精度目标。两个均值 CI 不重叠有助于展示明显差异，但重叠不自动证明“没有差异”；本报告的主判据是差值 CI。

**RU:** Полуширина интервала разности mmap около 6,93% её среднего не нарушает цель 5%: цель задана для средних отдельных групп. Непересечение отдельных интервалов наглядно показывает различие, но их пересечение не доказывает отсутствие эффекта. Основной критерий отчёта — интервал разности.

**知识点 / Понятия：**分布密度 / плотность；直方图与 KDE；配对设计 / парное сравнение；差值与倍数 / разность и отношение；统计模型的条件 / условия статистической модели。

## B7. 操作系统机制与资源 / Механизмы ОС и ресурсы

### B7.1. read/lseek 与 mmap 的路径 / Пути доступа

```text
read/lseek:
offset -> lseek -> read 24 bytes -> parse record -> follow child
Write adds: lseek to value -> write 8 bytes

mmap:
open/fstat -> map file -> access records by address -> unmap
Write: modify value through MAP_SHARED memory
```

**中文：**`lseek` 的首字母是小写 L，不是 I。它修改打开文件的当前位置，不等于移动物理磁盘磁头。即使 page cache 命中，read 仍有系统调用、检查和数据复制开销。

**RU:** В слове lseek первая буква — маленькая латинская L. Вызов изменяет позицию открытого файла, а не непосредственно перемещает головку диска. Попадание в page cache не отменяет стоимость системного вызова, проверок и копирования данных при read.

**中文：**mmap 建立虚拟地址映射，不是立刻把整个文件复制到私有数组。访问时可能由缺页处理建立映射；已有文件缓存也可能发生 minor fault。`MAP_SHARED` 的修改属于共享文件映射；`MAP_PRIVATE` 的私有写时复制不能等同于本实验的文件更新。

**RU:** mmap создаёт отображение виртуальных адресов, а не сразу копирует весь файл в частный массив. Отображение страниц может формироваться при обращениях. Даже при готовом page cache возможна minor fault. MAP_SHARED изменяет общее файловое отображение; частные copy-on-write изменения MAP_PRIVATE не эквивалентны этому обновлению файла.

**中文：**mmap 的源码每遍创建并撤销映射，所以进程内部 20 遍也会重复页表相关处理。普通内存读写不对应每顶点一次 read/write，但发生缺页时内核仍参与。它不是“完全绕开操作系统”。

**RU:** Реализация создаёт и удаляет отображение при каждом обходе, поэтому обработка отображений повторяется двадцать раз. Доступ к вершине не требует отдельного read/write, но при ошибке страницы работает ядро. mmap не означает полного обхода ОС.

### B7.2. 不要混淆四种机制 / Четыре разных механизма

| 概念 | 中文含义 | Русское объяснение |
|---|---|---|
| page cache | 内核缓存文件内容，主要在 RAM | Файловые данные, кешируемые ядром в памяти |
| CPU cache | 处理器缓存指令和数据缓存行 | Аппаратный кеш инструкций и данных |
| TLB | 缓存虚拟→物理地址转换 | Кеш трансляций виртуальных адресов |
| page fault | 缺失或受保护映射需要处理 | Исключение при отсутствии нужного отображения или прав |

**中文：**TLB miss 通常可以通过页表查询解决，不必触发 page fault；CPU cache miss 也不是 major fault。minor fault 通常不用读取后备存储；major fault 的解决需要 I/O。`major=0` 不等于所有磁盘 I/O 都为零，例如脏页写回不是这类缺页。

**RU:** Промах TLB обычно обслуживается поиском в таблице страниц без обязательной page fault. Промах CPU cache тоже не является major fault. Minor fault обычно не требует чтения из хранилища, major fault требует I/O для её разрешения. Ноль major faults не означает отсутствие всех операций с диском, например записи грязных страниц.

### B7.3. 怎样解释资源表？ / Как объяснить счётчики ресурсов?

这里全部是 **一个执行 20 遍的进程的平均资源量**。/ Значения относятся к среднему процессу из двадцати обходов.

| 组 | user，s | sys，s | minor faults | major | voluntary CS | involuntary CS |
|---|---:|---:|---:|---:|---:|---:|
| A | 0.621667 | 1.232000 | 134.00 | 0 | 1.63 | 5.43 |
| B | 1.270000 | 3.287667 | 134.13 | 0 | 1.67 | 10.97 |
| C | 0.013667 | 0.005667 | 3334.23 | 0 | 1.63 | 0.13 |
| D | 0.021667 | 0.032667 | 54591.20 | 0 | 1.57 | 0.17 |

**中文：**user 是用户态 CPU 时间，sys 是内核态 CPU 时间，wall 是整个命令等待结束的 elapsed 时间。sys 不是“等待磁盘的时间”。B 的 sys 比 A 约高 2.67 倍，与额外系统调用一致。GNU time 计数的命令与外层 wall 的包装范围不同，加上时钟限制，不能把 wall−user−sys 精确归因于 I/O 等待。

**RU:** User — процессорное время в пользовательском режиме, sys — в ядре, wall — прошедшая длительность команды. Sys не является временем ожидания диска. У B sys примерно в 2,67 раза больше, что согласуется с дополнительными вызовами. Различие границ учёта и шкал часов не позволяет точно приравнять wall−user−sys к ожиданию I/O.

**中文：**D 的 minor faults 很多，符合重复映射与写访问处理。一个文件约 2560 页、20 次映射，使“页面级事件在多遍累计”合理；但没有对每个 fault 做归因，不能断言每次都对应一个新物理页，也不能说有 54591 个唯一数据页。

**RU:** Большое число minor faults в D совместимо с повторными отображениями и обработкой записей. Файл содержит около 2560 страниц, поэтому страничные события могут накапливаться за двадцать обходов. Без отдельной трассировки нельзя утверждать, что каждая ошибка выделяет новую физическую страницу, или что существует 54591 разных страниц графа.

**中文：**voluntary CS 通常因等待 I/O、锁或休眠主动放弃 CPU；involuntary CS 通常因时间片或抢占离开 CPU。系统调用只可能切换特权模式，不必切换到另一个任务。即使 87 万系统调用，上下文切换也可以很少。

**RU:** Добровольное переключение обычно связано с ожиданием I/O, блокировки или сна; вынужденное — с вытеснением. Системный вызов меняет режим привилегий, но не обязательно выполняемую задачу. Сотни тысяч вызовов могут сопровождаться небольшим числом переключений контекста.

**中文：**计数器的小数是对整数计数求平均；GNU time 的 user/sys 显示步长约 0.01 s，所以短程序的 0.00 不能解释为没有 CPU 工作。主要均值相除：read/lseek/mmap≈61.91（读）、70.39（更新），只适用于当前原型程序和协议。

**RU:** Дробные счётчики получены усреднением целых значений. Разрешение user/sys около 0,01 с не позволяет считать 0,00 отсутствием работы. Отношения средних read/lseek к mmap составляют примерно 61,91 и 70,39, но относятся только к этим реализациям и протоколу.

**教材关联：**part1 第 15–16、20、34、38 页；part2 第 6–12、28–29 页；BPF 第 352–355、433–439、500–503 页。[mmap(2)](https://www.man7.org/linux/man-pages/man2/mmap.2.html) 说明共享和私有映射。

### B8.3. 为什么计时检查不能省略？ / Зачем контроль таймера?

| 时钟 | 中文 | Русский |

Для C интервалы перекрываются, поэтому малая стоимость вмешательства точно не установлена. Широкие интервалы perf для C/D имеют отрицательные нижние границы из-за малой выборки и симметричной аппроксимации, а не отрицательного физического времени.

**中文：**为何有的运行接近十分钟甚至更久？在大量顶点、ITER、多次重复和 strace 拦截叠加时，耗时会显著扩大；后台任务还可能影响准备阶段的 sync。判断是否完整应看阶段、参数、有效行和遍历数，不能用“越久越完整”作为标准。本报告的诊断 ITER=1，正式 ITER=20，目的不同。

**RU:** Большое число вершин, ITER, повторов и перехваты strace могут резко увеличить общую длительность; нагрузка может замедлить также подготовку. Полнота определяется этапами, параметрами и проверенными наблюдениями, а не продолжительностью. В отчёте диагностический ITER=1, основной ITER=20, поскольку задачи различаются.

### B9.2. 调用计数、RSS 与 perf：报告第 9.1 节 / Вызовы, RSS и perf

| 组 | read | write | lseek | 总调用 / Всего |
|---|---:|---:|---:|---:|
| A | 436907 | 2 | 436906 | 873850 |
| B | 436907 | 436907 | 873811 | 1747660 |
| C | 1 | 2 | 0 | 40 |
| D | 1 | 2 | 0 | 40 |

**中文：**B 比 A 多约 436905 次 write 和 lseek，对应逐顶点更新。A 的两次 write 并不代表更新了图：整进程统计包含标准输出。C/D 的 40 次包含启动、映射和输出；不能说 mmap 完全没有系统调用。mmap 的内存赋值不是每顶点一个 write。

**RU:** B добавляет примерно 436905 write и lseek, что соответствует обновлению вершин. Две записи A относятся к учёту целого процесса, включая вывод, а не обязательно к изменению графа. Сорок вызовов C/D включают запуск, отображение и вывод. mmap не устраняет все syscalls; присваивание памяти не является write на каждую вершину.

**中文：**诊断 time-v 示例中，A/B Max RSS=1440 KiB，C/D=11680 KiB；mmap 可把已驻留文件页面计入进程 RSS。RSS 是进程的驻留内存，不等于整个系统的文件缓存，也不能把多个进程 RSS 简单相加作为共享页面实际总量。

**RU:** В примере Max RSS равен 1440 КиБ для A/B и 11680 КиБ для C/D. Резидентные страницы отображённого файла могут учитываться в RSS. RSS процесса не равен всему системному файловому кешу; сумма RSS разных процессов может повторно учитывать общие страницы.

实际 perf 使用独立二进制 `/usr/lib/linux-tools-5.15.0-194/perf`，版本 5.15.209。包装器找不到 WSL 对应版本，不等于所有 perf 功能不可用。/ Использованный отдельный perf дал программные события; ошибка стандартной обёртки не доказывает невозможность всех функций perf в WSL.

| 组 | context-switches:u | cpu-migrations:u | page-faults:u，三次 / три повтора | cache-misses:u |
|---|---|---|---|---|
| A | 0/0/0 | 0/0/0 | 55/56/57 | 不支持 / не поддерживается |
| B | 0/0/0 | 0/0/0 | 56/57/57 | 不支持 / не поддерживается |

| D | 0/0/0 | 0/0/0 | 2777/2776/2775 | 不支持 / не поддерживается |

**中文：**`:u` 是实际请求的用户态过滤范围；不能拿其零值证明没有任何内核调度切换或迁移。`<not supported>` 是缺失指标，不是零，也不能从中算 CPU cache 命中率。page-faults 不是 cache-misses。

**RU:** Суффикс :u ограничивает область учёта пользовательским выполнением. Нули не доказывают отсутствие любых событий планировщика. `<not supported>` означает недоступный показатель, а не нулевое значение; по нему нельзя вычислять попадания CPU cache. Page-faults и cache-misses — разные события.

### B9.3. 背景负载：报告第 9.2 节 / Фоновая нагрузка

**中文：**两个 API 都以 Read、Cache、ITER=20 测三对 quiet/stress，共 12 个进程。额外负载是一个在 CPU 2 上运行的 Bash busy loop，它在文件准备之后启动，测量后终止；quiet/stress 顺序按重复交替。它制造 CPU 竞争，没有同时注入磁盘和内存压力。

**RU:** Для обоих API в режиме Read выполнены по три пары quiet/stress, всего двенадцать процессов с ITER=20. Один Bash busy loop закреплён на том же CPU 2, начинается после подготовки и завершается после измерения. Порядок условий чередуется. Это CPU-конкуренция, без отдельной искусственной нагрузки на диск и память.

| API | 状态 / Условие | wall 均值，s | s，s | involuntary CS 均值 |
|---|---|---:|---:|---:|
| read/lseek | quiet | 1.956309 | 0.013403 | 7.67 |
| read/lseek | stress | 4.281070 | 0.039363 | 533.67 |
| mmap | quiet | 0.036017 | 0.005826 | 0.67 |
| mmap | stress | 0.068207 | 0.007510 | 7.67 |

**中文：**平均时间约增长到 2.1883 倍和 1.8937 倍，强制切换也增加，与两个可运行任务争用同一逻辑 CPU 一致。这不是精确测出的“所有后台软件都让程序慢两倍”。N=3 和一种负载限制了外推。

**RU:** Средняя длительность выросла примерно в 2,1883 и 1,8937 раза, вместе с вынужденными переключениями. Это согласуется с конкуренцией двух runnable-задач за один логический CPU. Результат не означает, что любая фоновая программа всегда удваивает время; N=3 и один тип нагрузки ограничивают обобщение.

**知识点 / Понятия：**观测工具开销 / накладные расходы наблюдения；追踪与计数 / трассировка и счётчики；事件过滤 / фильтрация событий；CPU 队列竞争 / конкуренция за CPU；进程状态与抢占 / состояния процесса и вытеснение。

**教材关联：**part1 第 69–77 页；part2 第 6–12、28–29、42、49 页；BPF 第 33、352–355、1236 页。

## B10. 结论与边界 / Выводы и границы применимости

**可直接说的五条 / Пять основных выводов：**

1. **中文：**当前 Seq、Cache、10 MiB 条件下，更新明显慢于读取，两个 API 都支持事前方向假设。**RU:** При заданных Seq, Cache и 10 МиБ обновление медленнее чтения для обоих API и согласуется с гипотезой.
2. **中文：**mmap 的较少逐顶点系统调用与较低时间一致，但仍有映射、缺页及启动成本。**RU:** Меньшее число вызовов на вершину у mmap согласуется с меньшим временем, но остаются отображения, ошибки страниц и запуск.
3. **中文：**pilot 计算出的 N=30 达到了预设随机半宽目标；多跑不能解决所有系统误差。**RU:** N=30, выбранное по пилоту, достигло цели случайной полуширины; дополнительные повторы не устраняют все систематические ошибки.
4. **中文：**strace 和 CPU 竞争会改变结果，因此诊断与噪声数据未加入主样本。**RU:** strace и CPU-конкуренция изменяют выполнение; диагностические и шумные процессы не включены в основную выборку.
5. **中文：**结果是这些程序的缓存更新完成时间，不是文件已经可靠落盘的延迟，也不是 mmap 在所有场景下普遍更快的证明。**RU:** Измерено выполнение кешированного обновления этих программ, а не задержка гарантированной записи на носитель или универсальное преимущество mmap.

**中文：**关键限制包括 WSL 客体与主机共享资源、频率和温度未确认、硬件 cache-misses 不可用、时钟尺度差未独立校准。因为没有做绑核/不绑核的独立对照，不要宣称已经测出绑核改善的精确程度；其作用是本次控制方法。

**RU:** Ограничения включают общие ресурсы WSL и хоста, неподтверждённую частоту и температуру, недоступные cache-misses и отсутствие независимой калибровки часов. Отдельного сравнения с привязкой и без неё не было, поэтому её точный эффект не измерен; она является частью контроля окружения.

### C2. BPF 教材真正帮助什么？ / Что даёт книга о BPF?

**中文：**负载刻画先问程序做了什么：谁运行、读写什么、调用多频繁。本实验通过源码和 strace 明确每顶点操作，再用时间与资源计数解释现象。不能只看到慢就说“磁盘不够快”。

**RU:** Характеризация нагрузки объясняет, кто выполняется, что читает или меняет и какие операции часты. Здесь исходный код и strace показывают работу на вершину, а время и счётчики помогают объяснить результат. Само замедление не доказывает недостаточную скорость диска.

**中文：**USE 是对资源检查 Utilization（使用率）、Saturation（饱和/排队）、Errors（错误）。当前报告有 CPU 快照、内存和部分事件，但没有对所有设备完成完整 USE 审计。理解该方法可帮助老师追问“还缺什么证据”。

**RU:** USE проверяет использование, насыщение и ошибки ресурсов. В отчёте есть снимки CPU, памяти и некоторые события, но не полная USE-проверка всех устройств. Метод помогает определить, какие сведения ещё отсутствуют.

**中文：**分层下钻是从总延迟找 CPU、等待、文件系统或设备的贡献。当前只能说计数器“与机制一致”，没有把每一毫秒准确拆分到某条内核路径。时钟与工具范围限制也阻止直接把 wall−CPU 当完整 off-CPU 分解。

**RU:** Drill-down последовательно уточняет вклад CPU, ожидания, файловой системы и устройств. Здесь счётчики согласуются с механизмами, но точное разложение каждой миллисекунды по путям ядра не выполнено.

**中文：**BPF 可把程序附着到事件、在内核中聚合计数、延迟或堆栈；perf stat 计数不等于已经写了 BPF 程序。BPF 也有开销，事件频率越高、处理越复杂，影响越可能明显；不能保证换成 BPF 就零开销。

**RU:** BPF позволяет подключать программы к событиям и агрегировать счётчики, задержки или стеки в ядре. Запуск perf stat не означает разработки BPF-программы. У BPF тоже есть накладные расходы, зависящие от частоты событий и выполняемых действий.

**可拓展但未执行 / Возможное расширение, не выполненное здесь：**调度等待延迟、off-CPU 分析、文件缓存命中及真实块 I/O 追踪。/ Анализ ожидания планировщика, off-CPU, попаданий page cache и реального блочного I/O. 这些不是已有测量结果，不能在答辩中说已经得到。

## D. 高频追问：中俄简答 / Частые вопросы и короткие ответы

### 1. Почему четыре группы? / 为什么有四组？

**RU:** Две реализации умножены на два режима. Cache, размер и Seq фиксированы; no-cache не является фактором основной серии.

**中文：**两个实现乘两种操作。缓存、大小、Seq 固定，正式系列没有比较 NoCache。

### 2. Почему baseline шире варианта? / 为什么 baseline 比变体范围广？

**RU:** Это ознакомительная проверка программы и флагов по заданию. Для статистического вывода варианта использованы только A–D; baseline с N=1 не включён в основную выборку.

**中文：**它是课程的参数与功能熟悉步骤；正式结论只使用 A–D，N=1 的 baseline 不混入统计。

### 3. Почему mmap быстрее, хотя файл уже в кеше? / 文件已缓存，mmap 为什么还快？

**RU:** Кеш устраняет многие обращения к устройству, но не стоимость read/lseek на каждой вершине. mmap использует адресные обращения с другой обработкой страниц. Вывод относится к этим программам.

**中文：**缓存减少设备访问，没消除逐顶点 read/lseek 开销；mmap 通过地址访问，页面处理方式不同。

### 4. Может ли mmap иметь page faults после cat? / cat 之后 mmap 还能缺页吗？

**RU:** Да. Page cache и таблица страниц процесса — разные структуры. Страница файла может быть в RAM, но отображение или права доступа процесса ещё нужно установить.

**中文：**能。文件页已在 RAM，不代表本进程页表与访问权限已经建立。

### 5. Syscall равен context switch? / 系统调用就是上下文切换吗？

**RU:** Нет. Syscall меняет режим привилегий. Context switch меняет выполняемую задачу; он может произойти при блокировке или вытеснении.

**中文：**不是。系统调用改变特权模式；上下文切换改变执行任务，可能由阻塞或抢占引起。

### 6. N=30, ITER=20 — это 600 измерений? / 这是 600 次测量吗？

**RU:** Нет. Есть тридцать измеренных процессов на группу. Двадцать обходов внутри процесса объединены в один отсчёт.

**中文：**不是。每组只有 30 个进程计时，内部 20 遍合成一个观测。

### 7. N выбрано до результата? / N 真在正式结果前选择吗？

**RU:** Да. Правило сохранено до отдельного пилота, N рассчитано по пилоту и зафиксировано до основной серии. Основные данные для выбора не использовались.

**中文：**是。先保存规则，再按独立 pilot 选 N，正式数据没有参与选择。

### 8. Зачем Student t? / 为什么用 t？

**RU:** Дисперсия генеральной совокупности неизвестна и оценивается по выборке. При N=30 используется t с 29 степенями свободы; применимость зависит от условий наблюдений.

**中文：**未知总体方差，用样本估计。N=30 对应自由度 29，仍需考虑数据依赖等条件。

### 9. Узкий ДИ означает точный секундомер? / 窄 CI 说明秒表准确吗？

**RU:** Нет. Он описывает случайную неопределённость среднего. Систематическая ошибка часов может оставаться при любом N.

**中文：**不是。它描述平均值的随机不确定性，任何 N 下都可能还有系统时钟误差。

### 10. Если интервалы пересекаются, эффекта нет? / 区间重叠就是无差异吗？

**RU:** Не обязательно. Для нашего плана анализируется парная разность; её интервал не определяется простым пересечением отдельных интервалов средних.

**中文：**不一定。本计划看配对差值，其区间不能由两个均值区间是否相交直接决定。

### 11. Почему не удалить медленные точки? / 为什么不删慢点？

**RU:** Медленная корректная работа является частью наблюдений. Удаление после просмотра эффекта исказило бы оценку. Правило IQR использовано для описания, не удаления.

**中文：**有效的慢运行也是观测的一部分；看到效果再删会偏移估计。IQR 只标记。

### 12. Почему cache-misses не равно нулю? / 为什么不能填写零？

**RU:** Инструмент сообщил о неподдерживаемом событии. Это отсутствие измерения, а не измеренный ноль.

**中文：**工具说的是不支持该事件，属于未测得，不是测得为零。

### 13. Почему write в mmap почти не виден в strace? / mmap 写入为什么几乎没有 write？

**RU:** Обновление выполняется инструкциями записи памяти через MAP_SHARED. Его обработка может включать page faults и позднюю запись страниц, а не syscall write для каждой вершины.

**中文：**更新通过共享映射的内存写指令完成，可能引起缺页处理和后续页写回，不逐顶点调用 write。

### 14. Это измерение скорости SSD? / 测的是 SSD 速度吗？

**RU:** Нет, основная метрика — выполнение кешированного обхода и обновления программы. Гарантированная долговечная запись в основной режим не включена обязательным fsync/msync.

**中文：**主指标是缓存遍历与更新的执行时间，没有强制 fsync/msync 完成持久化，不能当 SSD 速度。

### 15. Зачем 10 МиБ и CPU 2? / 为什么 10 MiB 和 CPU 2？

**RU:** Размер задан вариантом и мал относительно RAM. CPU 2 — доступный логический процессор, выбранный для одинаковой привязки. Номер сам по себе не делает ядро самым быстрым.

**中文：**大小来自变体且相对 RAM 很小。CPU 2 是可用逻辑处理器，用于一致绑定；编号不说明它最快。

### 16. Почему числа нужно ограничить условиями? / 为什么结论需要限定条件？

**中文：**遍历由一个主执行线程顺序完成；启动包装进程不等于并行遍历线程。

### 18. Что делают fork и exec? / fork 和 exec 做什么？

**RU:** Fork создаёт новый процесс, exec заменяет образ текущего процесса программой. Повторные запускаемые команды поэтому имеют собственный жизненный цикл и стоимость запуска.

**中文：**fork 创建进程，exec 替换当前进程映像；反复启动命令有独立生命周期和成本。具体 Python 创建子进程的实现不必固定使用某个单一系统调用。

**RU:** Нет. Оно определяет совместное файловое отображение, но не заменяет блокировки для конкурентного доступа. В данном опыте нет нескольких параллельных модификаторов графа.

**中文：**不是。共享文件映射不代替并发同步；本实验没有多个并行写图任务。

| 文件 / Файл | 中文 | Русский |

**中文：**read/lseek 路径中，`traverse_chain` 调用 `read_vertex`，后者用 `graph_read` 读取记录；Write 再经 `write_value` 调用 `graph_write`。mmap 路径中，`map_graph_file` 使用 `MAP_SHARED`，Read 有 `PROT_READ`，Write 还加 `PROT_WRITE`；`traverse_mapped_chain` 通过地址读取并更新。两者都根据 child 决定下一顶点，并检查越界等异常。

**中文：**可用文件描述符不等于私有文件内容：open 建立访问入口，文件位置由 lseek 修改，close 释放描述符，但不自动替代 fsync 的持久化保证。mmap 建立成功后可以关闭 fd，映射仍有效，最终由 munmap 撤销。

**RU:** Дескриптор является средством доступа, а не отдельной копией файла. Open открывает доступ, lseek меняет позицию, close освобождает дескриптор, но не заменяет гарантию fsync. После успешного mmap fd можно закрыть, сохранив отображение до munmap.

### E3. 进程状态与线程概念 / Состояния процесса и понятие потока

**中文：**进程是执行中的程序实例及其地址空间、打开文件等资源；线程是执行单位，具有自己的寄存器状态与栈，同一进程的线程可共享地址空间和文件资源。Runnable 表示可执行但还在等 CPU，Running 表示正在执行，Blocked 表示在等待其他事件。它们与 User/Kernel 特权模式是两个维度：同一任务可以在运行中进入内核而不换任务。

**RU:** Процесс включает выполняемую программу и её ресурсы: адресное пространство, открытые файлы и другие структуры. Поток является единицей исполнения со своим стеком и состоянием регистров; потоки процесса могут разделять память и файлы. Runnable ожидает CPU, Running выполняется, Blocked ждёт другого события. Эти состояния отличаются от User/Kernel: задача может перейти в ядро, не сменившись другой задачей.

**中文：**本次 busy loop 与被测进程争用同一个 CPU，不是在共享 value 上做互斥锁测试。即使总机还有空闲 CPU，亲和性限制也可能让该 CPU 上有排队任务。

**RU:** Busy loop конкурирует с измеряемым процессом за один CPU, а не проверяет блокировки общего value. Даже при свободных CPU всей системы ограниченная affinity может создать очередь на выбранном CPU.

**教材关联：**part2 第 4–12、24–29、32–36、42 页；实际函数名已按随报告保存的源码核对。
