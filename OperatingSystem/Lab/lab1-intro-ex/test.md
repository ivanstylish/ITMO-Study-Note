## 1. Зачем сохранять сырые данные, а не только среднее?
### 为什么要保存原始数据，而不能只保存平均值？

**🇷🇺 Ответ:**

Сырые данные нужно сохранять, потому что среднее значение само по себе не показывает разброс результатов. По исходным измерениям мы можем посчитать стандартное отклонение и доверительный интервал, увидеть выбросы и при необходимости повторно обработать данные.

**🇨🇳 中文翻译：**

必须保存每一次测量的原始数据，因为平均值本身无法反映结果的波动程度。有了原始数据，我们才能计算标准差和置信区间，识别异常值，并在需要时重新分析实验结果。

**需要理解的知识点：**

- Среднее значение — 平均值
- Стандартное отклонение — 标准差
- Доверительный интервал — 置信区间
- Выбросы — 异常值

例如，两组实验的平均运行时间都可能是 10 秒，但第一组每次都接近 10 秒，第二组却可能在 5～15 秒之间波动。只保存平均值，就无法发现这种差别。

**简短回答：**

Среднее не показывает разброс. Сырые данные нужны для статистики, доверительного интервала и анализа выбросов.

## 2. Как вы запускали эксперимент, чтобы graph-seq не всегда шёл раньше graph-rand?
### 如何避免 graph-seq 总是在 graph-rand 前运行？

**🇷🇺 Ответ:**

Для сравнения двух графов можно чередовать порядок запусков. Например, в одном раунде сначала запускать graph-seq, потом graph-rand, а в следующем — наоборот. Это уменьшает влияние порядка запуска и систематического дрейфа, связанного с нагревом CPU, кешем и фоновой нагрузкой.

**🇨🇳 中文翻译：**

比较两个图时，可以采用交替执行的方式。例如第一轮先运行 graph-seq，再运行 graph-rand；第二轮交换顺序。这样能够减少运行顺序带来的系统性偏差，例如 CPU 温度升高、缓存状态变化以及后台负载变化。

**示例顺序：**

```text id="fjh6xa"
第 1 轮：seq  → rand
第 2 轮：rand → seq
第 3 轮：seq  → rand
第 4 轮：rand → seq
```

**Bash 实现：**

```bash id="r9stv7"
if (( i % 2 == 1 )); then
    graphs=(graph-seq.bin graph-rand.bin)
else
    graphs=(graph-rand.bin graph-seq.bin)
fi
```

**需要理解的知识点：**

- Чередование — 交替执行
- Порядок запуска — 运行顺序
- Систематический дрейф — 系统性漂移
- Воспроизводимость — 可重复性

**答辩注意：**

老师关心的不只是你有没有改变顺序，更重要的是为什么改变。

如果所有 seq 测量都集中在前面，所有 rand 测量都集中在后面，那么 CPU 温度、频率或后台任务随时间产生的变化，就可能被错误地当成 seq 和 rand 的性能差异。

注意：这里介绍的是同时比较 seq/rand 时的合理实验设计。如果某个实验变体只测试一种图，就应该按该变体实际使用的配置说明。

**简短回答：**

Я чередовал порядок: seq-rand, затем rand-seq. Это уменьшает влияние порядка запуска и систематического дрейфа.

## 3. Можно ли считать, что данные измерений распределены нормально?
### 可以认为测量数据服从正态分布吗？

**🇷🇺 Ответ:**

Нет, автоматически считать распределение нормальным нельзя. Время выполнения зависит от многих факторов операционной системы, поэтому могут появляться выбросы и асимметрия. Мы можем исследовать распределение с помощью гистограммы или Q–Q-графика. Использование t-интервала для среднего не означает, что исходные данные обязательно имеют нормальное распределение.

**🇨🇳 中文翻译：**

不能直接认为实验测量结果服从正态分布。程序运行时间会受到操作系统中很多因素的影响，因此数据可能出现异常值和偏斜。我们可以使用直方图或者 Q–Q 图检查数据分布。即使使用 Student t 置信区间，也不代表原始测量数据一定服从正态分布。

**需要理解的知识点：**

- Нормальное распределение — 正态分布
- Асимметрия — 偏斜
- Гистограмма — 直方图
- Распределение Стьюдента — Student t 分布
- Независимые измерения — 独立测量

**重要区别：**

原始测量数据的分布 ≠ 样本均值的抽样分布。

即使单次运行时间的分布并不完全符合正态分布，在测量足够独立、样本量适当且没有严重长尾等问题时，均值的统计推断仍可能是可靠的。

所以答辩时不要简单地说“因为 N=30，所以数据服从正态分布”。

**简短回答：**

Нет, нормальность нельзя просто предположить. Нужно анализировать распределение данных. t-интервал не доказывает нормальность исходных измерений.

## 4. Сколько измерений N рекомендуется сделать для каждой конфигурации?
### 每个实验配置应该测量多少次？

**🇷🇺 Ответ:**

Фиксированного универсального значения N нет. Число измерений нужно выбирать так, чтобы доверительный интервал имел приемлемую ширину. Сначала можно провести предварительные измерения, оценить разброс и затем определить необходимое N. В примере скрипта используется N=30, но это пример, а не универсальное требование.

**🇨🇳 中文翻译：**

不存在适用于所有实验的固定测量次数 N。应该根据所需的置信区间宽度选择测量次数。可以先做少量预实验，估计数据的波动程度，然后决定正式实验需要测量多少次。示例脚本使用 N=30，但这只是示例值，并不是通用规定。

**相关公式：**

标准误差：

SE = s / √N

置信区间：

CI = x̄ ± t × s / √N

其中：

- x̄：样本平均值
- s：样本标准差
- N：测量次数
- t：Student t 临界值

**需要理解的知识点：**

在其他条件相同的情况下，N 越大，标准误差通常越小，置信区间也通常越窄。

尤其要区分 N 和 ITER：

- **N**：独立启动程序进行测量的次数。
- **ITER**：一次程序运行中重复遍历图的次数。

例如 N=30、ITER=5，并不代表进行了 150 次相互独立的程序启动测量。

**简短回答：**

Универсального N нет. Его выбирают по разбросу данных и требуемой ширине доверительного интервала. В примере используется 30 измерений.

## 5. Какая утилита позволяет посмотреть характеристики Disk I/O?
### 什么工具可以查看磁盘 I/O？

**🇷🇺 Ответ:**

Для просмотра статистики дискового ввода-вывода используется iostat. Он показывает интенсивность чтения и записи, количество операций ввода-вывода, задержки и загрузку устройства. Если нужно посмотреть нагрузку отдельных процессов, можно использовать iotop.

**🇨🇳 中文翻译：**

可以使用 iostat 查看磁盘输入输出统计信息。它能够显示磁盘读写速率、I/O 操作次数、延迟以及设备利用率。如果想知道具体哪些进程正在使用磁盘，可以使用 iotop。

**常用命令：**

```bash id="sjv355"
iostat -x 1
```

每秒刷新一次扩展磁盘统计信息。

```bash id="01muxv"
iotop
```

查看各进程的磁盘 I/O 活动。

**需要理解的知识点：**

- Disk I/O — 磁盘输入输出
- IOPS — 每秒 I/O 操作次数
- Throughput — 吞吐量
- Latency — 延迟
- Utilization — 设备利用率

**容易被追问的区别：**

- `iostat`：主要观察磁盘设备整体的 I/O 性能。
- `iotop`：主要观察不同进程产生的磁盘 I/O 活动。

**简短回答：**

iostat показывает статистику дискового ввода-вывода, а iotop — нагрузку по отдельным процессам.

## 6. Какую важную для эксперимента информацию может показать lscpu?
### lscpu 可以显示哪些对实验重要的信息？

**🇷🇺 Ответ:**

lscpu показывает архитектуру и модель процессора, количество логических CPU, физических ядер и потоков, топологию процессора и размеры кешей. Для эксперимента это важно, потому что производительность зависит от характеристик CPU, а taskset позволяет закрепить процесс за определённым логическим CPU.

**🇨🇳 中文翻译：**

lscpu 可以显示 CPU 架构、型号、逻辑 CPU 数量、物理核心和线程数量、处理器拓扑结构以及缓存大小。这些信息对于实验很重要，因为 CPU 特性会影响程序性能，而且 taskset 可以把程序绑定到指定的逻辑 CPU。

**常用命令：**

```bash id="zrwnm7"
lscpu
```

**实验中的例子：**

```bash id="pd1td4"
taskset -c 2 ./out/graph_traverse ...
```

这里的 `2` 表示编号为 2 的逻辑 CPU，而不是“第二个物理核心”。

**需要理解的知识点：**

- CPU architecture — CPU 架构
- Logical CPU — 逻辑处理器
- Physical core — 物理核心
- CPU affinity — CPU 亲和性
- Cache hierarchy — 缓存层次结构

**答辩重点：**

如果老师问为什么实验需要 lscpu，可以解释：首先需要知道实验机器的硬件配置，其次需要确认可用的逻辑 CPU 编号，才能正确设置 taskset。

**简短回答：**

lscpu показывает архитектуру, модель CPU, количество ядер и потоков, топологию и кеши. Это нужно для описания системы и настройки taskset.

## 7. Как меняется результат измерения при одновременно работающем stress-ng? Почему?
### 同时运行 stress-ng 时，测量结果如何变化？为什么？

**🇷🇺 Ответ:**

При работе stress-ng время выполнения обычно увеличивается, а результаты могут стать менее стабильными. Причина — конкуренция за системные ресурсы: CPU, кеш, память или диск, в зависимости от типа нагрузки. Также может увеличиться количество переключений контекста. В результате появляется дополнительный системный шум.

**🇨🇳 中文翻译：**

同时运行 stress-ng 时，程序执行时间通常会增加，测量结果也可能变得不稳定。这是因为实验程序与 stress-ng 竞争系统资源，包括 CPU、缓存、内存或磁盘，具体取决于选择的压力类型。上下文切换次数也可能增加，最终导致额外的系统噪声。

**示例：**

```bash id="mm3yxw"
stress-ng --cpu 4 --timeout 60s
```

含义：

- `--cpu 4`：启动 4 个 CPU stress worker。
- `--timeout 60s`：运行 60 秒。

**可能产生的影响：**

```text id="ypvn9v"
stress-ng
    ↓
资源竞争
    ↓
CPU 调度 / 缓存竞争
    ↓
额外等待与上下文切换
    ↓
运行时间和测量波动可能增加
```

**需要理解的知识点：**

- Конкуренция за ресурсы — 资源竞争
- Фоновая нагрузка — 后台负载
- Переключение контекста — 上下文切换
- Системный шум — 系统噪声
- Планировщик — 调度器

**答辩注意：**

不能说 stress-ng 一定会让每次运行都变慢。实际结果取决于 CPU 核心数量、进程绑定方式以及 stress-ng 的负载类型。

例如，如果压力进程和实验程序没有争抢同一组 CPU 资源，影响可能比较小。

**简短回答：**

Время обычно увеличивается, а разброс становится больше, потому что stress-ng создаёт конкуренцию за ресурсы и дополнительный системный шум.

## 8. Что такое read() / seek()? Зачем нужны?
### read()/seek() 是什么？为什么需要？

**🇷🇺 Ответ:**

read() — это системный вызов, который читает данные из открытого файла в буфер процесса. lseek() изменяет текущую позицию в файле. В graph_traverse программа читает вершину с помощью read(), получает смещение следующей вершины и через lseek() переходит к её позиции. Так выполняется обход графа.

**🇨🇳 中文翻译：**

read() 是一个系统调用，用于将已打开文件中的数据读取到进程缓冲区。lseek() 用于改变文件当前的读取位置。在 graph_traverse 中，程序通过 read() 读取当前节点，获得下一个节点的偏移量，再通过 lseek() 跳转到对应位置，从而完成图的遍历。

**实验执行过程：**

```text id="0uth4g"
打开图文件
    ↓
read() 读取当前节点
    ↓
得到下一节点的偏移量
    ↓
lseek() 修改文件位置
    ↓
read() 读取下一节点
    ↓
重复直到遍历完成
```

**顺序图 graph-seq.bin：**

```text id="yos60j"
0 → 1 → 2 → 3 → 4 → 5
```

访问位置基本连续。

**随机图 graph-rand.bin：**

```text id="fhitzd"
0 → 537 → 21 → 802 → 145
```

访问位置分散。

两种图用于比较顺序访问和随机访问的性能差异。

**需要理解的知识点：**

- read() — 读取数据
- lseek() — 改变文件偏移量
- File descriptor — 文件描述符
- File offset — 文件偏移量
- System call — 系统调用
- Sequential access — 顺序访问
- Random access — 随机访问

**答辩注意：**

这道题建议使用准确的名称 `lseek()`，因为本实验中的 C 程序使用的是 POSIX `lseek()` 系统调用。

**简短回答：**

read() читает данные из файла, а lseek() изменяет текущую позицию в файле. В нашем обходчике они используются для перехода от одной вершины графа к следующей.


## 9. Как проверить, сколько страниц памяти занято файловым кэшем для графа после запуска?
### 如何检查程序运行后，图文件有多少内存页位于文件缓存中？

**🇷🇺 Ответ:**

Для этого можно использовать утилиту `vmtouch`. Она показывает, сколько страниц файла находится в файловом кеше операционной системы после выполнения программы.

**🇨🇳 中文翻译：**

可以使用 `vmtouch` 工具。它能够查看程序运行后，图文件有多少内存页位于操作系统的文件缓存（Page Cache）中。

**Команда / 命令：**

```bash
vmtouch graph-seq.bin
```

**Пример вывода / 输出示例：**

```text
Resident Pages: 1024/2048  50%
```

**Объяснение / 解释：**

- `Resident Pages`：驻留在文件缓存中的页面数量。
- `1024`：已经缓存的页面数量。
- `2048`：文件总页面数量。
- `50%`：文件页面的缓存比例。

**Важно / 注意：**

`vmtouch` 检查的是文件页缓存，而不是进程占用的全部物理内存。

**Краткий ответ / 简短答辩版：**

С помощью `vmtouch` можно проверить количество страниц файла, находящихся в файловом кеше ОС.

## 10. Какая опция у `stress-ng` создаёт нагрузку на CPU? Напишите команду, которая запускает 4 потока на 60 секунд.
### stress-ng 的哪个参数用于制造 CPU 负载？写出启动 4 个工作任务并持续 60 秒的命令。

**🇷🇺 Ответ:**

Опция `--cpu` создаёт нагрузку на процессор. Команда `stress-ng --cpu 4 --timeout 60s` запускает четыре CPU-воркера на 60 секунд. Это позволяет исследовать влияние фоновой нагрузки на производительность программы.

**🇨🇳 中文翻译：**

`--cpu` 参数用于制造 CPU 负载。命令 `stress-ng --cpu 4 --timeout 60s` 会启动 4 个 CPU 工作进程，持续运行 60 秒，用来研究后台负载对程序性能的影响。

**Команда / 命令：**

```bash
stress-ng --cpu 4 --timeout 60s
```

**Объяснение параметров / 参数解释：**

- `--cpu 4`：启动 4 个 CPU 压力工作进程（workers）。
- `--timeout 60s`：持续运行 60 秒。

**Важно / 注意：**

`--cpu 4` 启动的是 4 个 CPU workers，通常为独立进程，不一定是 4 个线程。

**Краткий ответ / 简短答辩版：**

Опция `--cpu` создаёт нагрузку на процессор. Команда: `stress-ng --cpu 4 --timeout 60s`.
