## 关键答辩问题

### 1. 怎样解释变体和四组？

Read vs Write 是比较因素；Cache、10 MiB、Seq 是固定条件。两个 API 分别研究，所以每个 API 有 Read 和 Write，共四组。Write 也是先读图，再增加 value，不是纯写磁盘吞吐测试。

俄语简述：

> Вариант сравнивает чтение и обновление при фиксированных Cache, 10 МиБ и Seq. Две реализации дают четыре конфигурации. В режиме Write программа читает цепь и обновляет value.

### 2. read/lseek 与 mmap 是什么？

lseek 修改文件位置；read 将数据放入用户缓冲区。当前源码每顶点读取一个 24 字节记录。Write 再定位并写 8 字节 value。mmap 把文件映射进虚拟地址空间，随后通过地址访问记录；页面不存在映射或访问权限需处理时，可能发生缺页。mmap 的内存赋值不对应每顶点一次 write 系统调用。

### 3. 为什么假设 Write 更慢？

依据代码：read/lseek 增加 lseek/write；mmap 增加修改共享页面的工作。事先只提出方向假设，没有规定精确倍数。方向分别在两种 API 中检验，不保证任何硬件和场景下都成立。

### 4. N 怎么来的？

事先设定 pilot 每组 10 次、目标 95% CI 半宽不超过 pilot 平均值的 5%，以及正式最低 30 次。用 pilot 的 s 反解 `t(0.975,n−1) × s / sqrt(n) ≤ E`，四组得到 3、3、26、14。按预设规则统一 `N=max(30,3,3,26,14)=30`，然后才开始正式测量。计算过程和锁定顺序在 `plan/`。

### 5. ITER=20 是 N=600 吗？

不是。一个进程只有一个计时结果，内部 20 遍归一化成 ms/遍历；N 是 30 个进程计时。不能将内部迭代伪装成 600 次独立采样。

### 6. 为什么预热和保留慢点？

每组先跑两个进程，这个数量在 pilot 前固定并从 CSV 中排除。每次正式进程前还恢复文件、sync、cat，以统一文件缓存方法。慢点只按 1.5×IQR 标记，全部保留；不能看到数据以后挑选删除。

### 7. 置信区间如何算？

`x=1000×wall/20`。平均值为求和除以 N；样本标准差分母为 N−1；SE=s/sqrt(N)。95% CI=`mean ± t×SE`，N=30 的 t=2.04523。A 的 SE=0.507331，半宽=1.037608 ms/遍历。

CI 反映平均值的随机不确定性，不是“95% 的单次运行会落在里面”。配对比较先按轮计算 Write−Read，再对这 30 个差值计算 CI。

### 8. N 翻倍会怎样？

若 s 和条件相近，30→60 时半宽约乘 0.69；希望半宽约减半，通常需 N 约变成四倍。更多测量不能消除时钟、固定工具开销和环境的系统误差。

### 9. Cache 指哪种缓存？

这里的主要控制对象是 Linux 文件 page cache；它不同于 CPU 的 L1/L2/L3 和 TLB。cat 预读文件；sync 完成此前写入，没有清空缓存。mmap 的 `--no-cache` 是建议与同步行为，不能等同于 O_DIRECT 或全局冷缓存。

### 10. 为什么 strace 下运行很慢？

一次 read/lseek 读进程约有 87 万系统调用，更新进程约 175 万，strace 会拦截它们。mmap 一次进程这里只有 40 次。诊断用于解释程序；正式测量不带 strace。诊断每次一个遍历，正式每次 20 个，不能直接混入同一平均值。

### 11. 0 个 major faults / perf cache-misses 不支持意味着什么？

major faults 为 0 与文件已预热相符，但不是所有磁盘 I/O 都为 0。minor faults 不等于读盘。perf 输出 `<not supported>` 表示未测得，不能填写为 0；`:u` 是实际的用户态过滤范围。上下文切换不等于每次系统调用。

### 12. 为什么保留计时检查？

本机确实出现了 MONOTONIC 与 RAW 约 7.8% 的尺度差，不能当作没有发生。主分析保留事先选择的 MONOTONIC，RAW 只检查同一批数据的方向；两个 API 的差值仍为正。现在的 5% 目标是平均值 CI 的随机半宽，不是绝对秒表准确度。报告用简短说明即可，无须放大量异常日志。

### 13. WSL 环境够不够？

WSL2 可完成课程程序。文件在 Ubuntu 的 ext4 家目录，taskset 固定客体 CPU 2。Windows 和 WSL 共享 CPU、内存和存储资源，Windows 后台仍有影响。当前不能确认物理核、固定频率或完整主机隔离，所以报告没有声称这些条件成立。

### 14. 为什么 10 MiB？直方图与 KDE 有什么区别？

10 MiB 来自变体，约为 WSL 客体总 RAM 的 0.13%，适合预读进 page cache。图的大小与文件缓存有关，不能因此说全部数据都放进 CPU L1/L2/L3。

直方图把数据分箱，每箱密度为次数/(N×箱宽)，各箱面积总和为 1。KDE 给每个点加一个平滑核再叠加，形状受带宽影响。当前用直方图，并对同一 API 的 Read/Write 使用共同箱边界；图能展示右移与慢点，但不证明数据服从正态分布。
