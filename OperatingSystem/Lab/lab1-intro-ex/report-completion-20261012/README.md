# Материалы лабораторной работы № 1

Вариант: **Read vs Write, Cache, 10M, Seq**.

## Содержание

- `report.typ`, `report.pdf` — исходник и итоговый отчёт. Сохранены правки автора; дополнены гипотеза, назначение baseline и диагностические счётчики.
- `assets/` — векторные рисунки средних с ДИ, наложенных распределений и порядка измерений.
- `data/formal/` — единственная основная серия: четыре группы по 30 процессов, ITER=20.
- `data/pilot/` — отдельный пилот: четыре группы по 10 процессов. Не включён в основное N.
- `data/baseline/` — 16 ознакомительных запусков, по одному обходу.
- `data/diagnostics/` — 48 диагностических процессов, по одному обходу.
- `data/background/` — 12 процессов контроля CPU-нагрузки, по 20 обходов.
- `plan/` — неизменённый план до пилота, расчёт N, журнал исполнения и снимок Windows.
- `code/lab/intro-exp/` — измерительные сценарии и исходники C; `code/lab/util/graphgen.py` — генератор курса.
- `analysis/` — воспроизводимая обработка сохранённых данных и итоговые таблицы.

Основная серия не смешана с baseline, пилотом, инструментальными и шумными процессами. Исходные CSV, журналы и технические временные метки не исправлялись. Календарные даты не используются в изложении результатов отчёта. Репозиторий GitHub указан как ссылка; изменения в него не отправлялись.

## Проверка расчётов без нового измерения

Из корня этой папки; требуется Python 3 со стандартной библиотекой:

```sh
python3 analysis/summarize_baseline.py
python3 analysis/analyze_auxiliary.py
python3 analysis/build_selected_assets.py --source-dir data/formal --series-status new_confirmatory
python3 plan/select_n.py --csv data/pilot/results.csv --plan plan/frozen-before-pilot-ru.md --analyzer analysis/build_selected_assets.py --output review/recomputed-n.json
```

Последняя команда пишет отдельную проверочную копию N и не заменяет зафиксированный до основной серии `plan/selected-n.json`. Повторная обработка даёт N=30 и те же численные таблицы. Хеши входных данных проверяются; вспомогательные исходные каталоги вне пакета не требуются.

Для сборки PDF из корня папки:

```sh
typst compile report.typ report.pdf
```

## Роли сценариев

`run_series.sh` собирает сырые результаты: компиляция, генерация Seq, восстановление и прогрев файла, два прогревочных процесса на группу, чередование A–D, проверка числа обходов и снимки окружения.

`mono_time.py` измеряет интервал вокруг одной команды и сохраняет три шкалы часов. Он нужен для основной метрики; GNU time округляет свой wall до 0,01 с, что слишком грубо для быстрых mmap-процессов.

`run_phase.sh` запускает пилот или основную серию и регистрирует события. Фаза `formal` проверяет N из сохранённого выбора. `select_n.py` выбирает N по отдельному пилоту. Эти роли не дублируют друг друга.

Остальные программы в `analysis/` работают только с сохранёнными данными. Они не запускаются во время измерения и не создают фоновую нагрузку. `summarize_baseline.py` разбирает 16 журналов; `analyze_auxiliary.py` обрабатывает диагностику и контроль нагрузки; `build_selected_assets.py` считает статистику основной серии и строит рисунки.

Полные снимки ранее использованных вспомогательных сценариев сохранены в `data/` как исходные материалы. Они не переписывались при редактуре отчёта.

## Повторный сбор

Для повторения на защите используйте новую рабочую копию папки в домашнем каталоге Ubuntu, чтобы сохранить исходный журнал планирования и результаты. Файл графа должен находиться на файловой системе гостя. Внутри `code/lab/intro-exp`:

```sh
CORE=2 N=10 ITER=20 WARMUP=2 bash run_phase.sh pilot
```

Затем вернитесь в корень новой рабочей копии и передайте `select_n.py` CSV только что полученного пилота; сохраните выбор до запуска основной серии. N новой серии берётся из этого выбора, а не автоматически из предыдущего отчёта. Сценарии диагностики и контроля нагрузки приложены отдельно в соответствующих каталогах `data/`.

## Ограничение таймера

При выполнении в WSL обнаружено расхождение MONOTONIC и RAW примерно на 7,75–7,80% по средним групп. Основной анализ сохраняет заранее выбранную метрику MONOTONIC; RAW используется для контроля тех же процессов. Направление эффекта Write−Read сохраняется на обеих шкалах. Узкий 95% ДИ означает малую случайную неопределённость среднего, а не подтверждённую абсолютную точность физической секунды. Причина расхождения не установлена.
