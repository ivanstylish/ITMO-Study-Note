## Диагностические инструменты и их влияние

Для анализа механизма выполнения использована отдельная диагностическая серия на последовательном графе 10 МиБ с прогретым страничным кэшем. Проверены четыре конфигурации: чтение и модификация посредством `read/lseek` и `mmap`. В каждом процессе выполнялся один обход. Для каждой конфигурации проведено по три запуска без инструментов, с `/usr/bin/time -v`, с `strace -c` и с `perf stat`; всего получено 48 корректных наблюдений. Порядок инструментов менялся циклически между повторениями. Перед измерениями проведён один дополнительный прогревочный запуск из 20 обходов для чтения каждой реализацией, исключённый из таблицы наблюдений.

Перед каждым запуском восстанавливался исходный граф, выполнялись `sync` и предварительное чтение файла. Внешний монотонный таймер охватывал `timeout`, `taskset`, диагностическую оболочку и программу; подготовка графа и задержка 0,2 с в этот интервал не входили. Все процессы закреплялись за логическим процессором 2, каждый запуск завершился с кодом 0 и обработал 436 905 вершин. Выбросы не исключались.

### Среднее время диагностического процесса

| Конфигурация | Без инструмента, с | `time -v`, с | `strace -c`, с | `perf stat`, с |
|---|---:|---:|---:|---:|
| `read/lseek`, чтение | 0,095819 | 0,097763 | 4,269392 | 0,126170 |
| `read/lseek`, запись | 0,229200 | 0,236564 | 8,466539 | 0,263034 |
| `mmap`, чтение | 0,003561 | 0,004246 | 0,005370 | 0,026668 |
| `mmap`, запись | 0,005708 | 0,006222 | 0,007267 | 0,017191 |

Для каждого среднего рассчитан двусторонний 95%-й t-интервал с двумя степенями свободы: `среднее ± 4,302653 · s / √3`. Полные границы, парные разности с запуском без инструмента в том же повторении и отношения средних приведены в таблице `auxiliary-tools-summary.csv`. Интервалы при N=3 для быстрых конфигураций широки; отрицательная нижняя граница симметричного t-интервала отражает низкую точность такой оценки, а не физически отрицательную длительность. Отношения средних используются как описательные оценки, без доверительных интервалов для самих отношений.

`strace` увеличивает среднее время `read/lseek` примерно в 44,56 раза при чтении и в 36,94 раза при записи. Для `mmap` соответствующие отношения равны 1,51 и 1,27. Это объясняется частотой перехватываемых системных вызовов. В первом диагностическом повторении чтение через `read/lseek` вызвало 436 907 операций `read` и 436 906 `lseek` (873 850 системных вызовов всего); запись — 436 907 `read`, 436 907 `write` и 873 811 `lseek` (1 747 660 всего). У `mmap` в обоих режимах зарегистрировано по 40 системных вызовов всего; обход вершин осуществляется обращениями к отображённой памяти. Счётчики включают загрузку программы, служебные обращения и вывод сообщений, поэтому они не равны исключительно операциям над графом. Время системных вызовов, указанное `strace`, не заменяет внешнее время всего процесса.

В первом повторении `/usr/bin/time -v` показал для `read/lseek` 0,03 с user и 0,06 с system при чтении, 0,04 с user и 0,18 с system при записи. Максимальный RSS составил 1 440 КиБ для `read/lseek` и 11 680 КиБ для `mmap`. Число major faults равно 0 во всех четырёх этих запусках; minor faults составили 69, 70, 231 и 2 790 соответственно. Показания user/system для быстрых `mmap` округлены до 0,00 с из-за разрешения вывода. Эта таблица описывает по одному запуску на конфигурацию и не является оценкой среднего потребления ресурсов всей основной серии.

`perf stat` сохранил доступные программные события `context-switches:u`, `cpu-migrations:u` и `page-faults:u`; аппаратное событие `cache-misses:u` имеет статус `<not supported>`. Суффикс `:u` ограничивает область учёта пользовательским выполнением, поэтому эти значения нельзя напрямую приравнивать к полным счётчикам `/usr/bin/time`. Отсутствующее аппаратное событие не записывается как ноль. Для сравнения времени инструментов используется внешний монотонный таймер, а не краткие внутренние интервалы, напечатанные `perf`.

Диагностическая серия предназначена для объяснения поведения программ и оценки влияния наблюдения. Она не объединяется с основной серией: в диагностике выполнялся один обход на процесс, в основной серии — 20. Инструменты не подключаются к основным измерениям времени.

## Контрольная фоновая нагрузка

В отдельном контроле измерено чтение последовательного графа с кэшем обеими реализациями без дополнительной нагрузки и при наличии одного процессора с непрерывным циклом, закреплённого за тем же логическим процессором 2. Точнее, фоновая нагрузка создавалась одним процессом `bash`, непрерывно выполняющим `while :; do :; done`; аппаратных процессоров этот тест не добавлял. Нагрузка запускалась после восстановления и прогрева графа, но до начала измеряемого процесса. Искусственная нагрузка на диск и память в этом контроле не создавалась.

Для каждого способа доступа сформированы три пары «без нагрузки / с нагрузкой». Порядок условий чередовался между парами. В каждом процессе выполнено 20 обходов; получено 12 корректных запусков. Внешний монотонный таймер охватывал также оболочки `timeout`, `taskset` и `/usr/bin/time`, с помощью которого сохранены процессорное время, переключения контекста и страничные ошибки. Подготовительные действия не измерялись.

| Доступ | Без нагрузки, среднее и 95% ДИ, с | С нагрузкой, среднее и 95% ДИ, с | Отношение средних |
|---|---:|---:|---:|
| `read/lseek` | 1,956309 [1,923013; 1,989604] | 4,281070 [4,183286; 4,378854] | 2,188 |
| `mmap` | 0,036017 [0,021545; 0,050490] | 0,068207 [0,049551; 0,086864] | 1,894 |

Средняя парная разность «с нагрузкой минус без нагрузки» равна 2,324762 с для `read/lseek` (95% ДИ [2,258131; 2,391392] с) и 0,032190 с для `mmap` (95% ДИ [0,013788; 0,050592] с). Все интервалы рассчитаны по трём независимым парам, а не по 60 внутренним обходам. Среднее число принудительных переключений контекста у `read/lseek` выросло с 7,67 до 533,67, у `mmap` — с 0,67 до 7,67. Во всех 12 запусках major faults равны 0. Эти наблюдения согласуются с конкуренцией за время процессора и объясняют необходимость контроля фоновой активности.

Этот контроль характеризует конкретную дополнительную CPU-нагрузку в WSL. N=3 и один вид нагрузки ограничивают обобщение; результат не является оценкой влияния любых фоновых программ, дисковой или смешанной нагрузки. Данные контроля не включаются в основную выборку.

### Ограничение вспомогательных измерений времени

В сохранённых вспомогательных журналах имеются расхождения календарной и монотонной шкал. Обработка использует исходные монотонные интервалы без пересортировки по календарным меткам и без исправления наблюдений. Календарные отметки не используются для вычисления длительности. Доверительные интервалы характеризуют вариацию записанных длительностей при указанном протоколе и не калибруют абсолютную точность часов виртуальной среды.
