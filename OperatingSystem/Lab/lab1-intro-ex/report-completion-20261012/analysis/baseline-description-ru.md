## Предварительные функциональные прогоны

До анализа основной серии проверена полная матрица из 16 конфигураций: две топологии (последовательная и случайно связанная цепь), два способа доступа (`read/lseek` и `mmap`), чтение и модификация, наличие и отсутствие ключа `--no-cache`. Для каждой конфигурации выполнен один запуск с одним обходом. Оба исходных графа имеют размер 10 МиБ (10 485 760 байт), содержат 436 905 вершин и созданы с `seed=427`; для последовательного графа генератор также подтвердил достижимость всех вершин и отсутствие циклов. Программы собраны с `gcc -O2 -Wall` и закреплены за логическим процессором 2.

Все 16 запусков завершились с кодом 0. В каждом журнале подтверждена обработка 436 905 вершин. Соответствие ключей режимам: чтение с кэшем — без ключей; запись с кэшем — `--write`; чтение с `--no-cache` — только `--no-cache`; запись с `--no-cache` — `--write --no-cache`. Основная серия данного варианта использует только последовательный граф и два режима с кэшем для каждой реализации.

Перед каждым запуском рабочий граф восстанавливался из исходного файла; затем выполнялись `sync` и предварительное чтение файла через `cat`. Эти действия находились вне измеряемого интервала. Глобальная очистка кэша не выполнялась. Для Linux вариант `read/lseek --no-cache` открывает файл с `O_DIRECT` и выполняет выровненные операции, в том числе чтение и модификацию покрывающих блоков при записи. Для `mmap` этот ключ имеет другую семантику: отображение по-прежнему использует страничный кэш; применяются подсказки `madvise`, а при записи дополнительно вызывается `msync(MS_SYNC)`. Поэтому обозначение `--no-cache` не означает одинаковое отключение всех уровней кэша у двух программ и не определяет единое состояние «холодного кэша».

### Записанное время одного предварительного обхода

| Топология | Доступ | Чтение, кэш, с | Запись, кэш, с | Чтение, `--no-cache`, с | Запись, `--no-cache`, с |
|---|---|---:|---:|---:|---:|
| Последовательная | `read/lseek` | 0,09 | 0,23 | 25,68 | 88,89 |
| Последовательная | `mmap` | 0,00 | 0,00 | 0,00 | 0,00 |
| Случайная цепь | `read/lseek` | 0,11 | 0,24 | 41,97 | 101,75 |
| Случайная цепь | `mmap` | 0,01 | 0,02 | 0,01 | 0,02 |

Источник — сохранённые журналы `/usr/bin/time -v`. Время выведено с шагом 0,01 с; запись `0,00` означает ограничение разрешения вывода, а не отсутствие затрат времени. Для последующих точных измерений быстрых конфигураций несколько обходов объединяются в один процесс и измеряются монотонным таймером.

В предварительных прогонах `read/lseek --no-cache` время ожидания значительно превышает суммарное процессорное время: для последовательного чтения записано 25,68 с wall при 0,09 с user и 1,88 с system; для последовательной записи — 88,89 с wall при 0,48 с user и 7,27 с system. Это согласуется с затратами на многочисленные операции прямого ввода-вывода. Число major faults равно 0 в 14 конфигурациях, равно 1 для чтения случайной цепи через `read/lseek` с кэшем и равно 3 для последовательного чтения через `mmap` с кэшем. Следовательно, предварительное чтение файла является описанием процедуры прогрева, а не доказательством отсутствия всех страничных ошибок. Нулевое число major faults также не означает отсутствие ввода-вывода через обычные системные вызовы.

Предварительные прогоны подтверждают работоспособность всех режимов и показывают необходимость уточнения семантики кэша. Один запуск на конфигурацию не позволяет оценить дисперсию и построить обоснованный доверительный интервал. Эти 16 наблюдений не добавляются к основной выборке и не используются как статистический пилот для выбора N.
