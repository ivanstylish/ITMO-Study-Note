## Цель и официальное задание

Цель работы — добавить запуск текстовых сценариев по строке `#!` в начале файла, сохранив обычную загрузку ELF и поведение неуспешного `exec()`.

[Официальное задание](https://github.com/secs-dev/xv6-riscv/blob/57dc72da888497f03084262bcbb40eed04e83eb4/doc/lab/shebang.md) требует добавить поддержку Shebang. Индивидуальный вариант, конкретные ограничения длины строки и глубины вложенности, а также подробный набор тестов в документе не определены. Ниже эти ограничения и правила разбора приведены как решения данной реализации. Вводная работа выполнена отдельно.

## Принятые правила

| Свойство | Решение реализации |
| --- | --- |
| Вложенность | Не более четырёх сценариев перед конечным ELF |
| Первая строка | Читаются первые 256 байт |
| Завершение строки | LF в пределах прочитанного окна или EOF после не более 255 байт |
| Путь интерпретатора | От 1 до 127 байт, в соответствии с `MAXPATH=128` |
| Пробелы | Перед путём и между путём и аргументом допускаются пробелы и табуляции |
| Необязательный аргумент | Весь остаток строки передаётся одной строкой с удалением крайних пробелов и табуляций |
| Кавычки | Сохраняются буквально, разбор как в shell не выполняется |
| Концы строк | Поддерживаются LF и CRLF |
| Относительный путь | Разрешается относительно текущего каталога, без поиска по `PATH` |
| Число аргументов | Сохраняется предел xv6: 31 строка и завершающий нулевой указатель |

NUL внутри первой строки отвергается. Строка без LF, заполнившая всё окно из 256 байт, также отвергается, чтобы не выполнить незаметно обрезанный путь или аргумент. Самоссылки и циклы интерпретаторов завершаются ошибкой по ограничению глубины.

## Ход работы

Ссылка на выполненную работу: [PR #2](https://github.com/ivanstylish/os-course-xv6-riscv/pull/2).

`sys_exec()` по-прежнему копирует пользовательские аргументы в память ядра и вызывает `kexec()`. В `kexec()` перед чтением полного заголовка ELF проверяются первые два байта файла. Если это не `#!`, выполняется исходный путь загрузки ELF. Такая предварительная проверка позволяет запускать и сценарии короче заголовка ELF.

Для сценария первая строка разбирается функцией `parse_shebang()`. Исходный `argv[0]` заменяется путём интерпретатора. Затем добавляются необязательный аргумент и путь текущего сценария. Остальные пользовательские аргументы сохраняются в прежнем порядке.

Например, для строки `#!/interp --mode text` и исходного списка `["old", "a", "b"]` новый список имеет вид `["/interp", "--mode text", "script", "a", "b"]`. Для пустого исходного списка всё равно передаются интерпретатор и путь сценария. Число аргументов проверяется до сдвига, а сам сдвиг выполняется с конца массива.

Обработка вложенности организована циклом, без рекурсивных вызовов `kexec()`. Перед открытием интерпретатора inode текущего сценария разблокируется и освобождается, а файловая транзакция завершается. Это предотвращает удержание старых блокировок при повторном открытии того же файла.

### Владение памятью и неуспешный exec

При обнаружении первого сценария выделяется одна страница `scriptargs`. Она содержит отдельный массив указателей `argv` и четыре независимых буфера строк. Благодаря этому пути и необязательные аргументы предыдущих уровней остаются действительными до копирования в новый пользовательский стек. Большие буферы не размещаются в одностраничном стеке ядра.

Исходный массив указателей, принадлежащий `sys_exec()`, не изменяется. Поэтому его первоначальные строки впоследствии освобождаются штатным кодом без повторного освобождения или потери указателей.

После загрузки конечного ELF аргументы копируются в новый стек с исходными проверками размера и выравнивания. Замена `p->pagetable`, размера процесса, точки входа и указателя стека происходит только после всех операций, которые могут вернуть ошибку. При отказе освобождаются новый образ, активный inode, транзакция и страница `scriptargs`. Старый образ процесса сохраняется, и `exec()` возвращает `-1`.

### Синхронизация запуска тестов

19 октября в трёх диагностических запусках CI для Intro исходный вывод QEMU содержал строку `$ wait for kill and reclaim 31`. Команда отправлялась после `time.sleep(1)`, и приглашение shell попадало в строку сообщения, из-за чего `re.match('wait', line)` давал ложный отказ. Общее для двух работ исправление Python-драйвера заменяет задержку ожиданием приглашения через `monitor(r'^\$ ', timeout=30)`. Ожидаемые результаты, регулярные выражения проверок и прежние тайм-ауты сценариев сохраняются. Для ожидания готовности shell добавлен отдельный предел 30 секунд.

### Наглядный запуск

```text
$ echo #!/echo INTERPRETER_OK > sbdemo
$ sbdemo hello xv6
INTERPRETER_OK sbdemo hello xv6
```

В этом примере echo показывает полученные аргументы. Язык сценария задаётся интерпретатором, а ядро отвечает за его выбор и запуск.

## Фактические результаты

| Проверка | Результат |
| --- | --- |
| Сборка ядра и `fs.img` | Успешно |
| Функциональные проверки Shebang | 41 из 41 |
| Полный `usertests` | `ALL TESTS PASSED` |
| `crash` | Пройдены все три сценария восстановления |
| `make fmt-check` | Успешно |

Функциональный набор проверяет обычный ELF, пустой `argv`, замену `argv[0]`, сохранение аргументов, необязательный аргумент, пробелы, CRLF, EOF, относительные пути, чтение тела сценария, границы первой строки и пути, переполнение `MAXARG`, четыре и пять уровней вложенности, самоссылку, цикл, отсутствующие файлы, каталоги и некорректный ELF.

Тестовый интерпретатор получает ожидаемые значения через унаследованный файловый дескриптор 3. Он проверяет каждый элемент `argv` и фактически читает тело сценария. Для отрицательных случаев успешный запуск интерпретатора возвращает специальный код 42, поэтому не может быть принят за ожидаемый отказ `exec()`.

В один из 41 случаев входят 48 последовательных неуспешных запусков, после которых корректный сценарий снова выполняется. Проверяется также продолжение выполнения после отказа из-за размера пользовательского стека. Повторные запуски дополняют проверку путей освобождения ресурсов в коде, но не заменяют отдельное измерение утечек памяти.

Три сценария `crash` проверяют восстановление журнала, освобождение осиротевшего файла и освобождение осиротевшего каталога. Полные локальные журналы сохранены в `OperatingSystem/Lab/xv6-notes/logs`, включая `shebang-functional-qemu.log`, `shebang-usertests.log` и `shebang-crash.log`.
