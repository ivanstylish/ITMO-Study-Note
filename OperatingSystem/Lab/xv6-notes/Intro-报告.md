## Цель и задание

Цель работы — изучить обмен данными между процессами через каналы, путь системного вызова и сохранённое состояние пользовательских регистров RISC-V.

[Официальное задание](https://github.com/secs-dev/xv6-riscv/blob/57dc72da888497f03084262bcbb40eed04e83eb4/doc/lab/intro.md) включает Pingpong, Dump и часть Dump2 со звёздочкой. Значение звёздочки в тексте не раскрыто. При этом [проверка ветки `lab-1`](https://github.com/secs-dev/xv6-riscv/blob/57dc72da888497f03084262bcbb40eed04e83eb4/.github/workflows/UserTests.yml) запускает `dumptests` и `dump2tests`, поэтому реализованы все три части.

Для Pingpong требуются передача `ping` от родителя ребёнку, ответ `pong`, вывод PID и сообщений, а также проверка с ёмкостью канала в один байт с последующим восстановлением исходного значения. Dump выводит младшие 32 бита `s2–s11` текущего процесса и возвращает 0. Dump2 возвращает полное значение выбранного регистра процесса, доступного вызывающему процессу по правилам родства.

## Ход работы

Ссылка на выполненную работу: [PR #1](https://github.com/ivanstylish/os-course-xv6-riscv/pull/1).

### Pingpong

Использованы два однонаправленных канала: первый передаёт `ping`, второй возвращает `pong`. Это решение исключает чтение родителем собственного сообщения. Официальное задание не ограничивает количество каналов одним.

После `fork()` каждый процесс закрывает ненужные концы. Функции `read_full()` и `write_full()` учитывают фактически переданное число байтов. Особенно важен цикл чтения: канал представляет поток байтов, поэтому один `read()` не обязан вернуть все четыре байта сообщения. Пятый байт буфера остаётся нулевым для безопасного строкового вывода. Родитель вызывает `wait()`, проверяет PID и код завершения ребёнка. Ошибки приводят к ненулевому коду завершения.

### Dump

Путь вызова: пользовательская обёртка, `ecall`, `usertrap()`, `syscall()`, `sys_dump()`, `dump()`. Номер вызова передаётся в `a7`, результат возвращается через `a0`.

Значения берутся из `myproc()->trapframe`, куда вход в ядро сохраняет пользовательские регистры. Общая функция `saved_sreg()` выбирает `s2–s11`. Для Dump значение явно преобразуется к младшим 32 битам и затем к `int`, чтобы вывод соответствовал формату `s2 = -12` и другим знаковым значениям официального теста. Текущие аппаратные регистры ядра и `proc.context` для этой задачи не используются.

### Dump2

Сигнатура пользовательского интерфейса — `dump2(int pid, int register_num, uint64 *return_value)`. Доступ разрешён самому процессу и его предкам. Обход родительской цепочки защищён `wait_lock`, запись целевого процесса проверяется под его блокировкой. Сохранённое значение копируется в локальную переменную. Блокировки освобождаются до `copyout()`, который записывает восемь байт в адресное пространство вызывающего процесса.

| Код | Причина |
| --- | --- |
| `0` | Значение записано успешно |
| `-1` | Нет права доступа к процессу |
| `-2` | Процесс с таким PID не найден |
| `-3` | Номер регистра вне диапазона 2–11 |
| `-4` | Не удалось записать результат в пользовательскую память |

Dump2 читает последнее сохранённое пользовательское значение. Вызов не останавливает другой процесс и не является полноценным отладчиком.

Диагностика 19 октября обнаружила `$ wait for kill and reclaim 31` при работающем `forphan`. В `test-xv6.py` задержка заменена ожиданием shell через `monitor()` с отдельным пределом 30 с. Пройдены четыре группы проверок драйвера и четыре запуска штатных наборов в обоих порядках.

## Команды проверки

Команды сборки и автоматических тестов выполнялись в Linux-контейнере из корня проекта `/xv6`.

```bash
make -j2 kernel/kernel fs.img
make fmt-check
sh ci/test/run.sh dumptests dump2tests
python3 test-xv6.py usertests
python3 test-xv6.py crash
```

Для интерактивной проверки использовался запуск:

```bash
make qemu CPUS=3
```

Внутри xv6 доступны следующие команды:

```text
pingpong
dumptests
dump2tests
dump2extra
```

Полная матрица Pingpong выполнена локальным сценарием, который временно меняет размер канала, принудительно пересобирает `kernel/pipe.o` и восстанавливает исходный файл в блоке `finally`.

```bash
python3 /lab-notes/scripts/verify-pingpong.py
```

Сценарий находится в общем локальном каталоге `xv6-notes`, смонтированном как `/lab-notes`. Он не относится к штатным средствам проверки школы.
