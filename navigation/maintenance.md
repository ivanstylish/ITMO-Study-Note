# 维护规则 · Правила ведения

[首页](../README.md) · [课程总览](courses.md) · [VS Code / GitHub 阅读](reading.md)

## 保持单一资料来源

课程原目录继续存放笔记、代码、报告和图像。30 门课程各使用唯一的课程 `readme.md`，合并新导航与原有讲座分类、各学期实验记录；同一课程跨学期共享入口。导航结构由 [catalog.json](catalog.json) 管理，学期归属来自已确认的课程安排。

新增真实资料后，在对应课程的 `resources` 中填写 `{ "label": "…", "path": "仓库相对路径" }`。可用类型为 `theory`、`labs`、`defense`、`exam`、`resources`。必须先有文件再增加入口；不要求每门课具备全部类型。`related` 填已有课程 id，生成双向关联时分别在两门课程配置。

```sh
node tools/generate-index.mjs
```

生成器将导航合并进现有课程 `readme.md`，只更新下列两组注释块之间的内容：

```md
<!-- kb:course-overview:start -->
自动生成的课程导览
<!-- kb:course-overview:end -->

<!-- kb:course-resources:start -->
自动生成的资料链接
<!-- kb:course-resources:end -->
```

这两组块以外的手工正文、讲座分类、各学期实验记录可以直接编辑，重新生成时保留。`kb:course-resources` 中的实验表允许只修改状态列，生成器按资料路径保留用户填写的状态；原手工清单中同编号的状态记录优先。该表的资料标签和链接仍由 catalog 管理，其他生成内容应通过 catalog 修改。

生成器也更新学期页和课程 / 实验总览；这些带有 `Generated by` 标记的整页内容应通过 catalog 修改。导航检查要求维护范围内的链接有效，历史笔记的断链另列清单。

VS Code 与 GitHub 是日常阅读入口，详见 [阅读指南](reading.md)。若要运行完整链接检查，可安装项目依赖后执行 `npm run kb:check`；[网站构建](website.md)按需使用，整体参考方向见 [项目设计方向](design.md)。

## 更新脑图

课程大纲与反向关联随导航一起生成。需要刷新可直接双击打开的离线脑图时，安装项目依赖后运行 `npm run mindmap:export`；网站构建也会自动更新这个文件。

## 元数据与状态

课程页的实验状态由本人维护，统一使用以下文字表示：

| 状态 | 含义 |
|---|---|
| ✓ 已通过 | 课程或实验已通过 |
| ○ 待通过 | 课程或实验待通过 |
| — 未标记 | 暂未填写状态 |

第 1–4 学期的课程与实验均已通过。跨学期课程按 `semesterStatus` 分别维护，因此俄语第 1–4 学期已通过，第 5 学期仍可独立记录。整门课程的状态在 catalog 的 `status` / `semesterStatus` 中维护；实验状态可直接修改课程页的状态列，重新生成时保留。新实验默认采用课程状态，也可在资料项上指定 `status`。

新笔记可逐渐使用下列可选 Frontmatter；旧笔记不批量补标签：

```yaml
---
course: os
semester: 5
type: defense
topic: [memory, file-io, measurement]
review: revisiting
---
```

- `course`：catalog 的课程 id；`semester`：实际学期，跨学期文件可省略。
- `type`：`theory` / `lab` / `exam` / `defense` / `cheatsheet` / `resource`。
- `topic`：少量可搜索的关键词，正文保留中文和俄语术语。
- 课程与实验的 `status`：`passed` / `pending` / `unmarked`，分别显示为 ✓ 已通过 / ○ 待通过 / — 未标记。学习笔记的可选 frontmatter 可另外记录复习进度。

## 路径与实验版本

新增专题推荐英文小写加连字符，例如 `quick-review.md`。旧文件名、大小写、实验编号及提交包保持原样；GitHub 链接使用标准 Markdown 相对路径，含空格的路径使用 URL 编码。

本地补回的不同实现放在 `local-source` 或 `local-variant`，避免覆盖已经收录的版本。每个快照有说明和 SHA256 清单；配置、密钥、IDE 缓存及构建产物不随源码归档。仓库此前已跟踪的依赖不会因为新增 `.gitignore` 自动从历史删除；本次不清理原始文件。

归档后的快照默认保持不变；若主动修改其中源码，要在审阅变更后同时更新 `import-manifest.json` 中对应文件的 SHA256 和字节数，保证持续校验有意义。导入工具会拒绝用本地版本覆盖内容不同的文件。课程导航按前述两组注释块更新，原笔记正文保留。

大 PDF / DOCX / PPT 和实验代码不复制进网站；网站投影可重新生成，不单独编辑。运行实验时查看对应项目的环境与启动说明。
