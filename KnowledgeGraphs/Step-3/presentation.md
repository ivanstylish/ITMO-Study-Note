## 3. 固定版本与运行 / Версия и запуск · 1:25–2:10

**屏幕操作 / На экране：** 在脚本中搜索 `def resolve_version`，指出锁文件逻辑，再展示准备好的终端日志。

### RU

Эта функция фиксирует версию игры в отдельном файле. При следующем запуске скрипт использует тот же выбор. Это помогает не смешивать описания из разных обновлений. В нашем наборе выбрана версия шестнадцать точка двадцать точка один и русская локализация. Для CommunityDragon также проверяется номер патча. Здесь показана команда для трёх чемпионов. Параметры включают дополнительные источники и загрузку значков. Для сбора всех чемпионов достаточно убрать ограничение по именам.

### 中文

这个函数把游戏版本固定在一个单独的文件中。下次运行时，脚本继续使用已保存的版本，避免混合不同更新中的描述。当前数据选择 `16.20.1` 版本和俄语本地化，并核对 CommunityDragon 的补丁号。这里展示的是采集三个英雄的命令，参数启用了补充来源和图标下载。删除英雄名称筛选参数，就可以采集全部英雄。

## 4. 数据整理逻辑 / Обработка данных · 2:10–3:00

**屏幕操作 / На экране：** 搜索 `def normalize_champion`，指出 `classes`、`stats`、`ability_id`、`description_text` 和 `source_url`。

### RU

Здесь исходные данные приводятся к единой структуре. Для чемпиона сохраняются идентификатор, имя, классы и характеристики. Для каждого основного умения создаётся отдельная запись с обозначением P, Q, W, E или R. Например, запись с идентификатором Lux:Q связана с чемпионом Lux. 这里把原始数据整理成统一结构。英雄记录保留标识符、名称、分类和属性，每个主要技能则单独生成一条记录，并标记 P、Q、W、E 或 R。例如，`Lux:Q` 这条技能记录关联到英雄 `Lux`。脚本同时保留原始 HTML 和去除标签的纯文本，以及版本和来源地址。`Mage`、`Support` 表示英雄分类，不能直接当成地图分路。
